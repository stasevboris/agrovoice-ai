# Локальный сервер AgroVoice

S-01/S-02: FastAPI, PostgreSQL, SQLAlchemy, Alembic, JWT и nginx. Реализованы
`GET /health`, `POST /auth/token`, `GET /me`, пакетная синхронизация и загрузка фото.
Телефон к серверу автоматически не подключается.

Из каталога `server/`:

```powershell
python setup_env.py
docker compose up -d --build
docker compose --profile test run --rm tests
```

API доступен только на этом ПК: `http://127.0.0.1:8027/health`, документация — `/docs`.
Миграции применяются перед запуском API. Секреты находятся в `.env`, в git и образ не попадают.
Тесты используют отдельную БД `agrovoice_test` и откатывают свои транзакции.
Рабочие осмотры телефона не импортируются.

Создать пользователя для локальной проверки:

```powershell
docker compose exec api python -m app.manage boris
```

Пароль вводится скрыто. Клиент получает bearer-токен, передав JSON
`{"username":"boris","password":"..."}` в `/auth/token`. Удалённое размещение,
TLS и подключение мобильной синхронизации — отдельные этапы. `docker compose down`
останавливает этот стенд и сохраняет его том с данными.

## Протокол синхронизации

`POST /sync/inspections` принимает `{"inspections": [...]}`. Элемент содержит
`id` (стабильный UUID клиента), `base_version` (0 для нового), `updated_at`
(ISO-время с зоной), `data` (осмотр с описанием фото). Полная схема и ограничения —
`/docs`. Ответ по каждому элементу: `accepted`, `unchanged` или `conflict` с
текущей серверной записью. Конфликт не перезаписывает данные: клиент сохраняет
локальный вариант для разрешения пользователем. Повтор одинакового запроса
после потери ответа возвращает прежнюю версию. Неизменившиеся payload и время
идемпотентны; изменённый payload требует текущую версию и более позднее время.

`GET /sync/inspections?after=0&limit=50` возвращает записи владельца, `next_after`
и `has_more`. Следующий запрос использует `next_after`. Серверная ревизия
выделяется под блокировкой учётной записи, поэтому параллельные отправки не
теряют обновления. Экспертная отметка — отдельное серверное поле; клиентское
`expert_status` запрещено схемой. UI/API специалиста ещё не реализованы.

Фото объявляется в `data.photos`: `id`, `sha256` (нижний hex), `bytes`.
`PUT /photos/{id}` принимает исходные байты с заголовком `X-Content-SHA256`;
`GET /photos/{id}` возвращает их только владельцу. Лимит фото 10 МиБ, не более
10 ссылок в осмотре. Размер и SHA проверяются до атомарной записи PostgreSQL
BYTEA. Неверный SHA, обрыв и превышение размера не оставляют частичных данных.
Повтор требует полное тело; загрузки по частям пока нет. UUID фото и его SHA
не переиспользуются для другого содержимого. Удаление ссылок не удаляет байты.
BYTEA подходит для локального стенда; объектное хранилище — отдельный этап.

Старые Android ID могут быть строками, не UUID. При A-20 нужно сохранять
устойчивое соответствие локального ID и UUID синхронизации, передавая исходное
имя в `data.legacy_id`. Переименовывать существующие записи или генерировать
новый UUID при каждом повторе нельзя. Синхронизация телефона пока не подключена.
