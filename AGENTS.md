# Инструкция для ИИ-агентов (Claude, Codex, Gemini, локальные модели)

Прочитай целиком перед любой работой. Короткая версия: **делай рабочие инкременты, не аудиты; не трать чужое время и GPU; не выдумывай цифры.**

## 1. Проект за минуту

- **AgroVoice AI** — дипломный проект Бориса (сдача — май 2027): офлайн-приложение Android для осмотра растений. Фото листа → нейросеть на телефоне (культура + состояние; целевая таксономия — 49 классов, 15 культур) → голосовое управление → справочник СЗР → журнал → сервер синхронизации. Фактическую поддержку в APK проверяй по STATUS и манифесту, не по целевой таксономии.
- План с карточками задач — [docs/ROADMAP.md](docs/ROADMAP.md). Текущее состояние — [docs/STATUS.md](docs/STATUS.md). Аудит и обоснования — [docs/AUDIT_AND_PLAN_2026-10-16.md](docs/AUDIT_AND_PLAN_2026-10-16.md).
- Пользователь пишет по-русски; отвечай по-русски, коротко и по делу.

### Память проекта: требования Бориса от 19.10.2026

- **Не ограничиваться YOLO.** Цель — надёжное распознавание в своей предметной области: устойчивость к теням и обычным условиям съёмки, различение предметов и листьев, неизвестных культур и известных состояний. Стол не должен получать диагноз кукурузы, чужой вид — подпись персика. Нужны проверяемые отказы/уточнения, а не убедительные объяснения ошибочного ответа.
- **Полное управление приложением без рук обычной русской речью.** Пользователь не должен заучивать список фраз. Рассматривать локальную малую LLM, контекстный диалог, гарнитуру и доступность по образцу голосового управления для незрячих. Работу внутри приложения и системные ограничения Android разграничивать явно.
- **Русский из коробки — важный критерий модели.** Очень лёгкую модель без русского можно рассматривать, если языковая адаптация оправдана измеренным выигрышем. Предусмотреть дообучение под функции AgroVoice и проверить его пользу; наличие модели на Hugging Face не доказывает пригодность для телефона.
- **Знания о лечении — из надёжной литературы.** Искать справочники, руководства и исследования, сохранять ссылки, редакции, регион и ограничения прав. Не считать найденную книгу готовым обучающим корпусом или проверенной рекомендацией. Дозировки — по правилам раздела 3.
- **Честная картина проекта.** Пользователю нужны реализация, версии, стек, расположение файлов, реальные результаты, пробелы и следующий шаг без сглаживания. Разделять факт, гипотезу, предложенный эксперимент и уже работающую функцию.
- **Логотип — приложенный Борисом рисунок.** Постоянный оригинал: `android-app/branding/logo-source.png`; генератор и инструкция рядом. Использовать этот исходник, не зависеть от временного вложения чата.
- **Вход в сохранённый контекст:** [STATUS](docs/STATUS.md) → [полный технический отчёт](docs/PROJECT_REPORT_2026-10-19.md) → [зрение](docs/research/ROBUST_VISION_2026-10-19.md), [локальный помощник](docs/research/LOCAL_ASSISTANT_2026-10-19.md), [литература](docs/research/AGRONOMY_LIBRARY_2026-10-19.md) → [ROADMAP](docs/ROADMAP.md). Не повторять завершённое исследование без новой причины; переходить к рабочему инкременту.
- **Рекомендации исследования не являются окончательным выбором Бориса.** D-FINE/DINOv2, Qwen3/Qwen3.5/FunctionGemma и база знаний с поиском — направления проверки. Не объявлять их внедрёнными или победителями без результатов. Полные материалы уже в тематических документах; оперативное состояние хранить только в STATUS.

## 2. Как выбрать работу

1. Открой `docs/STATUS.md` → раздел «Следующее».
2. Возьми первую карточку из ROADMAP с пометкой **агент** (или **агент+Б**), у которой выполнены зависимости.
3. Сделай её полностью по критерию «Готово, когда». Не расширяй объём: найденное по пути запиши в STATUS → «Найдено».
4. В конце: тесты зелёные, коммит, 3–5 строк в `docs/STATUS.md` (что сделано, чем проверено, что дальше).

## 3. Правила (выведены из ошибок прошлых сессий)

**Делай**
- Ограничивай время: на вопрос по данным — максимум 1 день. Сомнительный снимок или источник **исключи** и запиши причину, а не исследуй неделю.
- Пиши код, который читает человек и комиссия: один оператор на строку, понятные имена, короткие функции. Для Kotlin — обычный стиль Kotlin/Compose; для Python — PEP 8.
- Проверяй на деле: запусти тест, сборку или скрипт. В отчёте пиши, что именно запускал и что получилось.
- Пиши числа только из файлов результатов (`results.csv`, `evaluation.json`, `report.json`) со ссылкой на файл.
- Тяжёлые выходы (наборы, превью, JSONL > 5 МБ, WAV, APK, веса) клади только в каталоги из `.gitignore`: `ml-pipeline/dataset*/`, `ml-pipeline/.cache/`, `runs/`, `artifacts/`.

**Не делай**
- Не веди журналы сессий в README, PROJECT_GUIDE или отчётах («лимиты пятичасового окна», PID, «guard80» и т. п.). Состояние — только в `docs/STATUS.md`, ≤ 1 страницы.
- Не добавляй в скрипты «защитные» проверки SHA собственных исходников и не плоди контракты, реестры и preflight на сотни строк. Достаточно теста.
- Не запускай длинные обучения на домашней RX 9060 XT (Борис просил её не мучить). Обучение — через комплект `ml-pipeline/gpu_kit/` на арендованной GPU. Короткие проверки на CPU — можно.
- Не меняй порядок и ID классов в `ml-pipeline/allcrops/taxonomy_v1.json`: от него зависят ONNX и приложение. Новые классы — только новой версией таксономии (v2) с новым набором.
- Не запускай `gradlew connectedDebugAndroidTest` на телефоне Бориса: Gradle после прогона удаляет приложение вместе с журналом и фото. Инструментальные тесты — через `adb install -r` обоих APK и `adb shell am instrument`.
- Не трогай без явного разрешения Бориса: удаление данных и архивов, переписывание истории git, `git push`, установку системного ПО и драйверов, действия на его телефоне, публикацию чего-либо наружу.
- Не публикуй веса DEIMv2 (закрытая лицензия) и любые модели не через `prepare_model_release.py`. Лицензия проекта — AGPL-3.0, авторы данных — `ATTRIBUTION.md`.
- Не выдумывай диагнозы по картинке. Метка — только из источника данных или от специалиста.
- Не пиши дозировки препаратов из головы. Только из Госреестра РБ со ссылкой; без проверки специалистом — `status: draft`.

## 5. Команды (проверены 16.10.2026 на Windows этого ПК)

```powershell
# Python-тесты (30 шт., ~1 с)
.\ml-pipeline\venv\Scripts\python.exe -X utf8 -m unittest discover -s ml-pipeline\tests

# Android: JVM-тесты и сборка (JDK 25 в PATH, SDK в local.properties)
cd android-app; .\gradlew.bat testDebugUnitTest; .\gradlew.bat assembleDebug

# Набор allcrops_v1 (~15 мин, CPU) и пробный мини-набор
.\ml-pipeline\venv\Scripts\python.exe -X utf8 ml-pipeline\build_allcrops_v1.py --overwrite
.\ml-pipeline\venv\Scripts\python.exe -X utf8 ml-pipeline\build_allcrops_v1.py --limit-per-class 2 --out ml-pipeline\dataset_allcrops_v1_smoke --overwrite --no-previews

# Модели и голос для APK (чистый клон; только стандартная библиотека Python)
python android-app\fetch_assets.py

# Файлы GitHub Release из результатов обучения (ONNX, SHA256SUMS, карточка модели)
.\ml-pipeline\venv\Scripts\python.exe -X utf8 ml-pipeline\prepare_model_release.py runs\allcrops_v1\<run> --tag models-allcrops-v1 --update-config

# Комплект для GPU
.\ml-pipeline\venv\Scripts\python.exe -X utf8 ml-pipeline\pack_gpu_kit.py

# Проверить комплект без GPU (CPU, ~1 мин): распаковать и
python train_queue.py --smoke --device cpu
```

Окружение: Python 3.12 venv `ml-pipeline/venv` (Ultralytics 8.4.164, PyTorch CPU). WSL + ROCm для RX есть, но для обучения не используется (см. правила). Bash-утилиты в этой среде — Git Bash; Python печатает в консоль cp1251, поэтому запускай с `-X utf8` или `PYTHONIOENCODING=utf-8`.

## 6. Важные факты, которые легко перепутать

- Модель распознаёт **целый лист** и его состояние, а не пятно болезни. Уверенность — не вероятность болезни и не процент поражения.
- Экспорт для Android: `model.model.end2end = False` и `export(..., nms=None)` → выход `[1, 4+классов, 3549]` при 416. Голова YOLO26 one-to-one (`[1,300,6]`) приложением не поддерживается.
- Домены: **field** = PlantDoc (фото в поле); **lab** = PlantVillage, OLID, Zenodo (одиночные листья). Решения о модели принимаются по field.
- PlantDoc test (236 снимков) содержит несколько старых почти-дубликатов train. Прежние метрики clean v1/v2 условные (`HISTORICAL_OVERLAP_ADDENDUM_2026-10-05.md`).
- Числа из исходного описания темы (mAP 93,4 %, WER 6,8 %, 25–40 мс) **не подтверждены** и не используются.
- Телефоны для проверки: Redmi Note 7 (Android 13), Samsung A56; желательно Redmi 9T.

## 7. Готово, когда (для любой задачи)

- Код собирается, тесты зелёные (и новые тесты на новую логику).
- Проверено запуском; результат и команда записаны в STATUS.md.
- Нет тяжёлых файлов в коммите (`git diff --stat --cached`).
- Коммит в формате `область: что сделано` (например, `android: per-model classes in manifest v3`), без `push`, пока Борис не разрешил.
