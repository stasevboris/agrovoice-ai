## Где должна появляться новая информация

- Короткое изменяемое состояние — `STATUS.md`; карточки работ — `ROADMAP.md`.
- Инструкция повторяемого действия — `guides/`; описание устройства системы — `architecture/`.
- Исследование с источниками — `research/`; проверка проекта — `audits/`.
- Результаты опыта — `experiments/<серия>/`; телефонные измерения — `android/<серия>/`.
- Старый обзор, заменённый новым, — `history/`. У каждого отчёта должна быть дата и область применимости.
- Новые тяжёлые файлы — в игнорируемых `artifacts/`, `runs/`, `ml-pipeline/dataset*/` или `.cache/`.
  Старые доказательства в `docs/experiments` не переносить без проверки потребителей путей.

При расхождении описания и реализации проверять исходник, манифест и файл результата.
Исследовательская рекомендация не заменяет решение Бориса. Внешние цены, лицензии,
версии и доступность перепроверяются перед использованием, даже если ссылка открывалась раньше.
