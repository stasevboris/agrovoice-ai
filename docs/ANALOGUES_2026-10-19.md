# Аналоги AgroVoice AI и выбранные улучшения

Проверено 19.10.2026: поиск Google, чтение первичных страниц во встроенном браузере. Приложения аналогов не устанавливались, их модели не запускались. Описание функции производителем подтверждает наличие заявления о функции, но не её качество. Числовые показатели точности и скорости из рекламных страниц здесь не сравниваются: общего тестового набора нет.

## Постановка задачи

Цель — обосновать практические улучшения дипломного приложения для осмотра растений. Результат: список аналогов с проверяемыми источниками стека, сравнение применимости и законченный инкремент Android с тестами. Ограничения: офлайн-анализ на имеющихся телефонах, Kotlin/Compose + ONNX, отсутствие нового обучения и платных API, неизменная таксономия. Рекомендации препаратов требуют источников РБ и проверки специалистом.

Сравниваем зрелые продукты и открытый дипломный проект. Критерии: автономность, прозрачность реализации, работа с качеством входа и неопределённостью, журнал и экспертная проверка, стоимость интеграции. Переносим проверяемые идеи поведения; смена архитектуры требует отдельного доказательства пользы.

## Анализ и решения

**Факт:** Nuru и открытый PlantiX показывают подход с локальным анализом; коммерческие API показывают другой способ интеграции. **Вывод:** оснований заменять Compose/ONNX на Flutter/TFLite или внешний API нет. Перенос потребует перепроверки предобработки, экспорта, боксов и производительности, не решая автоматически проблему качества полевых данных.

**Факт:** Kindwise рекомендует хорошо сфокусированные и освещённые фото [K2]. **Вывод:** полезно помочь пользователю переснять плохой кадр. **Предположение:** простые измерения яркости и детализации дадут полезные подсказки на наших телефонах. Это предположение ещё требует проверки на размеченных примерах качества. Поэтому подсказка не останавливает модель и не объявляет снимок пригодным для диагноза.

**Факт по нашему коду:** список боксов формируется после порога и фильтра культуры. **Вывод:** пустой список не доказывает, что растение здорово или на снимке нет листа. Пустой ответ должен объяснять это и предлагать пересъёмку, а не побуждать снижать порог до появления любого ответа.

**Факт:** Plantix предлагает экспертное сообщество, Agrio — совместный журнал, Kindwise — справочные примеры. **Вывод:** журнал и будущая проверка агрономом важнее добавления локального чат-бота. Пользовательская оценка остаётся обратной связью, а не автоматически подтверждённой меткой для обучения. Запись измерений качества вместе с ответом даст материал для проверки полезности подсказок.

| Вариант улучшения | Решение | Причина / условие применения |
|---|---|---|
| Подсказки по фото без запрета анализа | Реализовано | Работают локально без новых моделей и runtime-зависимостей; пороги явно обозначены как некалиброванные |
| Понятный пустой результат и единая формулировка для TTS | Реализовано | Устраняет ошибочную трактовку «не найдено = здорово» без выдуманного порога надёжности |
| Измерения качества и состояние ответа в JSON | Реализовано | Журнал и экспорт сохраняют контекст результата для дальнейших испытаний |
| Жёстко отклонять размытые кадры | Отложено | Резкий фон может скрывать размытый лист, гладкий лист — получить ложное предупреждение. Нужна калибровка, желательно проверка области листа |
| Top-2/3 и отказ по близости классов | Отложено | Нужны исходные оценки классов и проверка на field-val. Сейчас приложение поддерживает разные выходы YOLO, DETR и двухстадийных моделей; для всех нельзя одинаково восстановить альтернативы из готовых боксов |
| Голосование разных листьев за один диагноз | Не выбрано | Разные листья одного растения могут иметь разные состояния; согласие не равно правильности. Результаты сохраняются по листьям |
| Отсев «не лист» | Следующая задача данных D-02 | Порог уверенности не заменяет негативы и испытания на неизвестных объектах |
| INT8 / переход на TFLite | После M-03/M-04, отдельный эксперимент | Сравнивать конкретные экспорты на field-val, затем на телефонах. Чужой единичный эксперимент не доказывает непригодность INT8 для целого семейства сетей |
| Справочник, участки и подтверждение специалистом | По существующему ROADMAP | Подтверждаются сценариями аналогов; требуют данных, специалиста и отдельного инкремента, а не расширения этой задачи |

## Реализованный инкремент

- `PhotoQuality.kt`: средняя яркость, доля очень светлых пикселей, дисперсия лапласиана. Максимальная сторона копии — `256`, пропорции сохраняются, маленькие фото не увеличиваются. Пороги `45`, `210`, `0.25`, `60` — параметры реализации, **не экспериментальные результаты**. Версия метода `whole_frame_luma_laplacian_v1` позволяет отличать будущую калибровку.
- Приоритет подсказок: непроверяемый размер → темнота → пересвет → мало деталей. Чёрный/белый кадр больше не получает совет о фокусе вместо совета об освещении. «Нет предупреждения» не означает «кадр хороший».
- `PhotoFiles.measureQuality` вызывается в рабочем потоке перед инференсом. Подсказка выводится под фото в обеих раскладках. Время `inference_ms` и `pipeline_ms` по-прежнему относится к детектору, не включает новую проверку качества.
- `spokenAnalysis` читает ту же подсказку, затем отдельные предварительные результаты по листьям. При отсутствии боксов и экран, и голос объясняют ограничение; названия состояний модели не подменяются эвристикой.
- В отчёте добавлены `photo_quality` (метод, размеры копии, измерения, `calibrated: false`, `blocking: false`) и `assessment` (`no_detections`, `photo_warning`, `preliminary`). Это описательные состояния, **не диагностический отказ и не измерение достоверности**. Старые JSON не требуют миграции: `InspectionJournal` уже сохраняет весь объект `prediction` и экспортирует его целиком.

Это часть X-02 **после получения фото**. Подсказки в живом видоискателе до нажатия затвора, размер листа в кадре и калибровка остаются открытыми; X-02 целиком не закрыта.

## Проверка и ограничения

Команда из `android-app`: `./gradlew.bat testDebugUnitTest assembleDebug assembleDebugAndroidTest`.
JVM-тесты и обе сборки прошли. Покрыты экспозиция, детализация, насыщенные области, узкие фото, размер копии, некорректные размеры, голосовой ответ и JSON round-trip. Результаты JVM: `android-app/app/build/test-results/testDebugUnitTest/`; локальная сводка — `artifacts/verification/photo_quality/report.json`.

APK собран; установка, визуальная проверка и инструментальные тесты на телефоне не выполнялись. Проверка синтетических изображений устанавливает поведение кода, но не качество диагностики или долю полезных подсказок. Следующая проверка: реальные фото на Note 7/A56, экспертная оценка качества кадра, частота ложных предупреждений, время проверки и читаемость подсказок при крупном шрифте. Пороги корректировать по отдельной выборке качества, не по финальному test болезней.
