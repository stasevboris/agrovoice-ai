# Что ставить на обучение AgroVoice

Это инструкция для Бориса. Оперативное состояние — [STATUS](../STATUS.md).
Подготовленные данные и их фактические количества —
[основной отчёт](../data/TRAINING_PREPARATION_REPORT.json) и
[новое пополнение](../data/WEB_RESEARCH_PREPARATION_REPORT.json).
Ниже **предложенный экспериментальный бюджет**, не измеренная длительность и
не обещание качества. Новые модели в рамках поиска не обучались.

## Что выбрать первым

Для первого исследования: **одна пара YOLO26n без/с просмотренными негативами**
на строгом `dataset_vision_training_v1`. Это проверит пользу данных на дешёвом
контроле. Потом такая же пара S, затем D-FINE-N на тех же снимках. Не запускать
сразу все архитектуры, seed, разрешения и языковые модели.

Для выпуска модели на все целевые классы сначала исправить геометрию отсутствующих
train-классов: `corn__healthy`, `cucumber__bacterial_wilt`, `cucumber__downy_mildew`.
Строгий набор пригоден для ограниченного сравнения, но его нельзя выдавать за
полную поддержку taxonomy_v1. Классы и ID не переупорядочивать.

Старый самодостаточный baseline-комплект `agrovoice_gpu_kit_20261016.zip` и его
`train_queue.py` остаются отдельным маршрутом allcrops_v1. Он использует другой
набор/рецепт и оценивает test после каждого запуска. Его результаты нельзя
смешивать с новой абляцией как будто условия одинаковы. Инструкция:
[gpu_kit/README](../../ml-pipeline/gpu_kit/README.md).

## Где лежат данные и для чего они подходят

Все пути ниже относительно `ml-pipeline/`; на GPU основной исследовательский
архив раскрывает их в `data/`. Внутри каждого набора есть `report.json`.

| Каталог | Вход для опыта | Использование |
|---|---|---|
| `dataset_vision_training_v1` | `annotations/train.json`, `val_field.json`, `crops.jsonl` | Основные рамки целого листа; одинаковые train/field-val для детекторов; вырезки для классификаторов |
| `dataset_nonplant_openimages_v2` | `manifest.jsonl`, просмотренные `labels/` | Только train-негативы добавлены в `train_with_negatives`; val/test используются отдельно для отказа |
| `dataset_unknown_beans_screened_v1` | `train.jsonl`, `val.jsonl`, `test.jsonl` | Фасоль вне таксономии. После exposure train её test уже не новый вид |
| `dataset_unknown_deepweeds_v1` | Те же manifests | Разделение по видам/дате/камере; не брать test-виды в обучение |
| `dataset_web_leaf_presence_v1` | `train.jsonl`, `crops.jsonl` | Новые обычные фото: наличие листа и выбранные вырезки вида. Состояние неизвестно; **не добавлять в 49-классовую детекцию** |
| `dataset_optima_rgb_v1` | `train.jsonl`, `source_task_train_coco.json` | Дополнительные представления или отдельная задача областей поражения. Исторический v1, только train; **не рамки целого листа** |
| `dataset_assistant_ru_v1` | `train.jsonl` → `messages` | Малый синтетический seed управления; не реальные записи пользователей |
| `dataset_intents_ru_massive_v1` | Исходные русские utterance/intent/slots | Вспомогательная задача, другая система действий; не смешивать вслепую с AgroVoice |
| `dataset_asr_ru_fleurs_v1` | Аудио и `train/val/test.jsonl` | Общий русский ASR; не заменяет команды в шуме теплицы |

У каждого рядом `.report.json` с SHA256 и проверкой CRC. Дополнение не переписывает
основной архив. Не копировать в обучение кандидатов, `excluded.json` и превью.

## Эпоха, запуск и seed

**Эпоха** — проход по train. **Запуск** — отдельное обучение с фиксированными
данными, архитектурой, seed и гиперпараметрами. **Seed** управляет случайностью;
другой seed проверяет устойчивость результата, а не добавляет данные.
`best` выбирается по val; `last` нужен для продолжения, это не обязательно лучшая модель.

Предлагаемая очередь после короткого запуска/экспорта:

| Этап | Запуски | Предложенный предел | Что решаем |
|---|---|---|---|
| Проверка тракта | Одна модель на маленькой train/val-выборке | 1 эпоха | Данные читаются, loss конечен, результат сохраняется, экспорт поддерживается |
| Пилот негативов | N без негативов; N с train-негативами | До 20 эпох, patience 5, общий seed `20261019` | Есть ли направление эффекта; после короткого пилота не объявлять победителя навсегда |
| Проверка размера | S без/с негативами, если аренда позволяет | Такой же бюджет и seed | Помогает ли размер; отдельное сравнение латентности ещё впереди |
| Новый детектор | D-FINE-N; S только при оправданном эффекте N | Сначала короткий forward/export, затем ограниченный пилот | Есть ли выигрыш на тех же train/field-val; не переносить YOLO LR/расписание вслепую |
| Финалисты | Две выбранные конфигурации, одинаковый набор seed | До 60 эпох, patience 15; seed `20261019`, `20261020`, `20261021` | Среднее и разброс, стоимость, ошибки по культурам. Три запуска суммарно на конфигурацию, а не ещё три поверх подходящего полного запуска |
| Представления | DINOv2 ViT-S/14 + линейная голова; MobileNetV3 контроль | Голова до 20 эпох, patience 5; затем отдельный план fine-tuning | Польза признаков на вырезках и в полной цепочке с предсказанными рамками |
| Помощник | Правила/классификатор; Qwen исходный; один SFT/LoRA | Сначала без обучения; SFT 1–3 эпохи с выбором по val | Точное действие+аргументы, отрицания/отмена; избежать запоминания маленькой синтетики |

Все эти числа — начальные ограничения опыта. Если кривая val продолжает улучшаться,
это основание запланировать более длинный **сопоставимый** опыт, а не бесконечно
продлевать только понравившуюся модель. Ранняя остановка не гарантирует отсутствие
переобучения. Для D-FINE первые короткие эпохи могут быть недостаточны для ранжирования.

## Как запустить новую YOLO-пару

На арендованной машине, в окружении с проверенными CUDA/PyTorch/Ultralytics;
веса брать из baseline-комплекта. Дома запускать только конфигуратор и тесты.
Конфигуратор нужно выполнить **после распаковки на GPU-машине**, потому что он
пишет абсолютные пути. Он берёт field-val из подготовленного COCO и не добавляет test.

```bash
python configure_yolo_pilot.py --data /work/data/dataset_vision_training_v1 --out /work/pilot_config
yolo detect train model=/work/weights/yolo26n.pt data=/work/pilot_config/train.yaml imgsz=416 epochs=20 patience=5 batch=16 optimizer=AdamW lr0=0.001 cos_lr=True seed=20261019 workers=4 device=0 project=/work/runs/pilot name=n_baseline
yolo detect train model=/work/weights/yolo26n.pt data=/work/pilot_config/train_with_negatives.yaml imgsz=416 epochs=20 patience=5 batch=16 optimizer=AdamW lr0=0.001 cos_lr=True seed=20261019 workers=4 device=0 project=/work/runs/pilot name=n_negatives
```

Файл конфигуратора в репозитории:
[configure_yolo_pilot.py](../../ml-pipeline/gpu_kit/alternatives/configure_yolo_pilot.py).
Его создание файлов проверено на реальных данных; команды обучения выше здесь
не запускались. Начальный `batch=16` — выбор для старта, не измеренный оптимум GPU.
При OOM снизить batch одинаково для сравниваемой пары и записать изменение.
Не запускать эти команды на домашней RX.

`data.yaml` исходного строгого набора использует смешанный val; для этой абляции
использовать именно новые конфиги с **field-val**. Чекпойнт от mixed-val и
чекпойнт от field-val нельзя считать выбранными по одному критерию.
Отрицательные val-кадры проверяются дополнительно: они не заменяют field-val.

Для D-FINE уже есть [configure_dfine.py](../../ml-pipeline/gpu_kit/alternatives/configure_dfine.py)
и [рецепт](../../ml-pipeline/gpu_kit/alternatives/README.md). Он использует field-val.
Совместимость полного D-FINE forward/export и мобильного runtime ещё не проверена.
Сценарии DINO/SFT — планы ограниченных опытов, не готовые протестированные trainers.

## Когда останавливать и что сохранять

Перед арендой определить длительность сеанса и цену часа. После измерения первых
эпох оценить бюджет: время оставшихся эпох + validation/export + упаковка.
Стоимость = часы × действующий тариф; тариф и скорость этой GPU здесь неизвестны.
Если времени мало, закончить одну сопоставимую пару, а не оставить несколько моделей
без результатов. Для нового CLI-пилота жёсткий лимит аренды задаётся у провайдера;
встроенной защиты старого `train_queue.py` у этих двух CLI-команд нет.

Сохранять `args.yaml`, `results.csv`, `weights/best.pt`, `weights/last.pt`, версии
пакетов/GPU, хеши manifest, список train/val, отчёт по field-val и негативам.
Оценка: mAP и recall по классам; доля предметов с выданным диагнозом; принятие
unknown; risk–coverage. Один суммарный mAP не отвечает на вопрос «стол стал кукурузой?».

Порог отказа и конфигурацию зафиксировать по val. Test — после выбора; старый
PlantDoc test считать историческим, собственный новый полевой test держать закрытым.
Для новых веб-фото собственного test не создано. Фото/вырезки одного наблюдения
никогда не разводить по split; найденный дубль теста исключать из train.

После выбора: ONNX обычной головы для текущего Android → паритет PyTorch/ONNX →
замер Note 7/A56 с разрешения Бориса → проверка всего голосового сценария →
`prepare_model_release.py`. Экспорт, INT8 и скорость — отдельные испытания;
серверная точность ещё не делает модель пригодной для телефона.
