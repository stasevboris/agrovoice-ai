# Данные и модели для следующего обучения AgroVoice

Проверка источников: 19.10.2026. Это продолжение [исследования зрения](ROBUST_VISION_2026-10-19.md),
[помощника](LOCAL_ASSISTANT_2026-10-19.md) и [аналогов приложения](../ANALOGUES_2026-10-19.md).
Результат — подготовленные файлы, воспроизводимые сборщики и отбор кандидатов.
Новые модели не обучались; победитель по точности/скорости на телефоне ещё неизвестен.

## Постановка и границы

Нужно улучшить автономное распознавание целого листа и состояния, научить систему
отказываться на предметах/неизвестных видах и понимать естественные русские команды.
Результат должен быть пригоден для обучения на арендованной GPU и последующей
проверки Note 7/A56. Код Android, порядок taxonomy_v1, телефон и системное ПО в
этом изменении не меняются. Данные других культур используются отдельно для OOD,
а не объявляются новыми поддерживаемыми болезнями.

«Как можно больше» трактуется как широкий поиск **источников**, затем ограниченный
отбор данных с полезным происхождением. «Только лучшее» — короткая очередь
экспериментов по критериям: полевой перенос, корректные отказы, русский язык,
возможность мобильного экспорта, лицензия и стоимость интеграции. Рейтинг чужих
серверных бенчмарков не заменяет проверку нашего приложения. Полностью перечислить
все закрытые продукты и постоянно обновляющиеся датасеты невозможно; ниже указаны
охват, исключения и фактически проверенные источники, без заявления об исчерпывающем рынке.

## Почему данные разделены именно так

- **Болезни:** исходные метки источников; никакой диагноз не назначен по внешнему виду.
  Для COCO сохранена рамка конкретного листа, а не одна метка на все листья кадра.
  Автоматические объединения пятен Zenodo и fallback-рамки во весь кадр исключены.
  Пересечения исходных групп/точных хешей между split и конфликтующие подписи
  приводят к исключению; искусственные повторы редких фото не увеличивают объём.
- **Beans:** исходный split, проверка pHash поворотов/отражений против существующего
  индекса PlantDoc/PlantVillage/OLID/Zenodo и между выборками. После обучения на
  фасоли её test — проверка на уже встречавшейся неизвестной культуре, не на новом виде.
- **DeepWeeds:** фактический train — Lantana/Parthenium, val — Prickly acacia/Rubber vine,
  test — Siam weed/Snake weed. Дни съёмки одной камерой, пересекающие эти split,
  исключены (включая все выбранные Parkinsonia); затем pHash и конфликтующие группы. `Negative` источника означает
  отсутствие целевых сорняков, **не** отсутствие растения: этот класс исключён.
  Независимость хозяйств не установлена; Австралия не заменяет собственную Беларусь.
- **Предметы:** поиск по отрицательным Plant/Tree/Flower сначала дал фотографии
  видимых листьев. Этот автоматический пилот отклонён целиком и помечен
  `training_ready=false`. Новый отбор требует положительного предметного класса,
  отрицательного Plant, проверенной лицензии изображения и просмотра. Решения по
  каждому ID сохранены в `external/nonplant_review_v2.json`; сомнительные фоны,
  трава, листья и зелень в еде исключены. Это визуальный скрининг ассистента,
  не экспертная фитопатологическая разметка. Деление по автору, по одному фото автора;
  проверены близкие копии. Разные авторы не доказывают независимость всех сцен.
- **Команды:** парафразы одного сценария остаются в одном split. Есть отрицания,
  исправление культуры, границы номера фото, недоступные действия, отсутствие
  результата, отмена, диктовка текста, составной запрос и отказ от выдуманного лечения.
  Это небольшой явно синтетический корпус. Он не доказывает свободное понимание
  речи людей; новый контекстный JSON-исполнитель ещё не встроен в приложение.
- **Речь:** исходные FLEURS split сохранены. Кавычки TSV не интерпретируются как CSV,
  float WAV проверены по частоте, каналам и длине из таблицы. Нельзя выдавать пол
  диктора за speaker_id. Фоновый шум теплицы и агрономическая лексика здесь не измерены.

## Выбор моделей: лучшие кандидаты для этого проекта

Это **инженерный приоритет испытаний**, а не измеренный рейтинг качества.
Карточки/репозитории ниже прочитаны повторно для проверки актуальности; старые
результаты проекта не сравниваются с чужими COCO/серверными метриками.

| Роль | Первый выбор для испытания | Сильная альтернатива / почему не первая |
|---|---|---|
| Детектор на телефоне | **YOLO26n/s как контроль + [D-FINE-N/S](https://github.com/Peterande/D-FINE)** | [RT-DETRv2](https://github.com/lyuwenyu/RT-DETR) — резерв при проблемах D-FINE. Готовый YOLO runtime снижает цену внедрения; преимущество нового детектора надо подтвердить на одинаковых данных |
| Представления и неизвестное | **[DINOv2 ViT-S](https://github.com/facebookresearch/dinov2) + простая голова**, затем мобильный ученик | [DINOv3](https://github.com/facebookresearch/dinov3) — современный challenger, но другие условия лицензии. Ни один DINO сам по себе не готовый диагност или гарантированный OOD-детектор |
| Мобильный классификатор | **MobileNetV3-Large** как уже знакомый контроль; [MobileNetV4-Conv-Small](https://huggingface.co/timm/mobilenetv4_conv_small.e2400_r224_in1k) как кандидат | EfficientNet-B0 — прежняя сравнимая линия. Каскад должен выиграть в полной цепочке, а не только на идеальных вырезках |
| Русское управление | **[Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B)** без thinking и **[Qwen3.5-0.8B](https://huggingface.co/Qwen/Qwen3.5-0.8B)** для специального SFT | Qwen3-1.7B/Qwen3.5-2B для A56 после измерения памяти; Qwen2.5-0.5B-Instruct — дешёвый контроль. предобучение интересно для transfer, однако конкретная модель/экспорт/лицензия и
цена на Note 7 ещё не проверены. Название Nano не означает одинаковый размер у
разных семейств. DEIMv2 остаётся закрытым локальным экспериментом по правилам проекта.

**Сильнейший контраргумент смене архитектуры:** ошибки вызваны распределением данных,
разметкой и отсутствием отказа; более сложная сеть может проиграть простому YOLO с
негативами. Поэтому первая пара опытов меняет только данные, следующая — архитектуру.
**Контраргумент LLM:** небольшой intent/slot-классификатор и правила могут оказаться
достаточными и быстрее. Сравнить их на тех же русских сценариях; SFT не считать
полезным до измерения прироста против исходной модели.

## Продуктовый рынок и решение о стеке

Сохраняются проверенные выводы [обзора аналогов](../ANALOGUES_2026-10-19.md).
Повторно открыты страницы [Plantix API](https://plantix.net/en/plantix-intelligence/api-toolkit/),
[Agrio API](https://agrio.app/Agriculture-API/) и [Kindwise crop.health](https://www.kindwise.com/crop-health).
Они полезны как ориентиры фото-сценария, справки и экспертной эскалации, но их API не
удовлетворяют требованию автономности и не дают открытых обучающих весов/данных.
PlantVillage Nuru остаётся примером офлайн-подхода для конкретных культур;
историческая работа Nuru не доказывает современное качество AgroVoice.

Закрытые архитектуры и цены без подтверждённого тарифа не выдумываются. Перенос на
другой UI framework или покупка облачного API не выбраны: они не устранят
неправильный диагноз без сети. Коммерческий продукт, отдельная нейросеть и набор
данных — разные объекты сравнения, их нельзя ранжировать одной «точностью».

## Что считать успехом следующего этапа

1. На одних данных сравнить YOLO без/с негативами; затем D-FINE и классификационный
   путь. Зафиксировать field-val, unknown-val и критерии до выбора checkpoint.
2. Измерить по культурам/состояниям пропуски, ложные диагнозы на предметах,
   принятие неизвестного и risk–coverage. Виды DeepWeeds test до этого не использовать.
   Калибровка по одному маленькому набору предметов не достаточна.
3. Для помощника сравнить правила/малый классификатор, исходные Qwen и SFT на точном
   действии+аргументах. Ошибки отрицания и команды внутри заметки — отдельные критические
   ошибки. FLEURS WER отдельно от завершения сценария голосом.
4. Проверить ONNX/GGUF/квантизованный артефакт и всю цепочку на телефоне: холодный
   запуск, p50/p95, память, нагрев, отказ/отмена. Сейчас этих измерений нет.
5. Собрать собственный закрытый field/hands-free test. Для фото хранить растение,
   участок/сессию, культуру и источник метки, пару свет/тень; одна пара и растение
   не расходятся по split. Для речи — согласие, speaker/session, устройство/гарнитуру,
   условия шума и реальные исправления. Не заменять эти данные синтетикой или
   автоматически принятыми диагнозами приложения.

Готовность к пилоту высокая по наличию файлов и проверяемости конвертации;
уверенность в превосходстве какой-либо новой модели **пока низкая**. Следующее
обоснованное решение даст ограниченное сравнительное обучение, а не ещё один
круг массового скачивания зеркал.
