# Локальные модели для программирования на компьютере Бориса

Проверено 3 октября 2026 года. Ryzen 7 5700X, Radeon RX 9060 XT 16 ГБ, 32 ГБ DDR4 2666, Windows 11. **Рекомендация для первого испытания: Qwen3.5-9B Q4_K_M через LM Studio/Vulkan.** Резерв для правок кода — Qwen2.5-Coder-14B-Instruct Q4_K_M. Это выбор по доступным весам, функциям и запасу памяти; их скорость и качество на этом компьютере ещё не измерены.

## Движок на AMD / Windows

| Среда | Что подтверждает первоисточник | Решение для этого компьютера |
|---|---|---|
| [LM Studio](https://lmstudio.ai/docs/app/system-requirements) | Windows x64, AVX2, рекомендуется от 16 ГБ RAM; [changelog](https://lmstudio.ai/changelog/lmstudio) описывает Vulkan на Windows и выбор AMD GPU | Самый удобный первый запуск: GUI, GGUF, контроль контекста/VRAM, локальный API. Выбрать Radeon и актуальный llama.cpp Vulkan runtime; фактическую загрузку GPU проверить по логу |
| [Ollama](https://docs.ollama.com/gpu) | RX 9060 XT есть в Linux ROCm-таблице, но отсутствует в Windows ROCm/HIP-таблице. **Vulkan поддерживает дополнительные GPU Windows/Linux и включён по умолчанию при наличии backend** в текущей документации | Возможный второй вариант. Не объявлять карту несовместимой с Ollama вообще и не обещать native HIP. Проверить актуальную Windows-сборку, Vulkan backend, `ollama ps` и серверный лог |
| [llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md) | Есть Vulkan backend и сервер для локального инференса | Вариант для воспроизводимой CLI-конфигурации. Зафиксировать release/build, GGUF, параметры и chat template; сложнее GUI, зато можно точно протоколировать |

WSL/ROCm для YOLO уже проверен, но это не доказательство работы любого LLM-движка в WSL. vLLM/SGLang оставляем на позднее: их установка на Radeon требует отдельной проверки совместимости и не нужна для первых базовых задач. **Готовую среду AgroVoice-ML не менять ради локального агента.**

## Начальная конфигурация и границы ожиданий

1. После завершения study10_v2 загрузить **одну** Qwen3.5-9B-Q4_K_M.gguf (5 680 522 464 байта в зафиксированной revision). Разместить модели на F: в отдельной папке, не внутри Android assets/датасетов.
2. Обновить движок в LM Studio, выбрать RX 9060 XT/Vulkan, начать с **8192 токенов** для небольших заданий и одной активной сессии. Затем пробовать 16k при достаточном запасе VRAM. Не начинать с объявленных в карточке сотен тысяч токенов.
3. Установить полную выгрузку весов на GPU, если она помещается; проверить фактические allocated VRAM и backend. При ошибке загрузки сначала уменьшить контекст/отключить дополнительные vision-компоненты, затем выбирать меньший quant. CPU offload на DDR4 2666 может резко замедлить агента — конкретного tokens/s пока нет.
4. Для базовых задач можно проверить режим без длинного thinking, если движок и модель корректно поддерживают его. Не заменять chat template вручную на шаблон другой модели. Для tool calls нужны поддержка модели **и** корректный parser движка.
5. Поднять API на `http://127.0.0.1:1234/v1`; подключить агент из [инструкции](LOCAL_AGENTS_SETUP_2026-10-03.md). Название протокола OpenAI-compatible означает локальный интерфейс; само по себе оно не отправляет код в платный облачный API.

Базовые задачи для этой связки: объяснить отдельный файл, обновить документацию по имеющимся JSON, исправить маленькую UI-ошибку, добавить простую функцию, разобрать stack trace. Изменение протокола обучения, составление диагнозов по неясным меткам, выбор агрохимии и сложные миграции требуют отдельной проверки результата человеком.

## Как получить собственные цифры

Сначала проверить одну небольшую задачу с чтением файла, правкой и возвратом корректного diff. Затем сравнить Qwen3.5-9B Q4 и Qwen2.5-Coder-14B Q4 на одинаковых десяти небольших задачах в копии репозитория: одинаковые вводные/контекст/лимит ответа, свежая сессия, известные критерии успешности. Отдельно измерять время загрузки, first token, обработку prompt, tokens/s, пик VRAM/RAM, правильность tool calls и прохождение нужной проверки кода. Скорость генерации текста не равна доле решённых задач.

Повторные измерения скорости проводить с прогревом и несколькими независимыми запросами, а не по одному красивому ответу. Пока такого эксперимента нет, ни «N токенов/с», ни «точность кодинга X%» в проектном журнале не заявляются. В этой сессии веса LLM не скачивались, движки/агенты не устанавливались; GPU занят сравнением YOLO.
