# Функции AgroVoice и система достижений

> Каталог предложений, а не список реализованных функций. Room и архив с фото появились после исходного текста; история растения и достижения ещё не внедрены. Их очередь и критерии — [план развития](../DEVELOPMENT_PLAN_2026-10-19.md), карточки X-04…X-07 в ROADMAP.

Проверка: 19.10.2026. Это каталог идей и проект реализации по поручению Бориса;
перечисленные расширения не объявляются работающими в APK. Текущее состояние —
[STATUS](../STATUS.md), приоритеты реализации — [ROADMAP](../ROADMAP.md).

## Что ищем и как выбираем

Цель — полезное офлайн-приложение для осмотра растений и защищаемый диплом:
каждая функция должна решать наблюдаемую проблему и иметь проверяемый сценарий.
Ограничения: Kotlin/Compose, слабый Android, русский голос, отсутствие сети,
предварительный характер диагноза. Идеи оцениваем по пользе агроному,
стоимости интеграции, доступности исходников и возможности испытания.
Смена стека ради чужого демонстрационного приложения не требуется.

## Достижения: конкретная реализация для AgroVoice

Полезные исходники Seek:

- [Определения значков](https://github.com/iNaturalist/SeekReactNative/blob/main/utility/dictionaries/badgesDict.ts).
- [Локальная схема состояния](https://github.com/iNaturalist/SeekReactNative/blob/main/models/BadgeRealm.ts): постоянный ключ, порог, факт и дата получения.
- [Условия и пересчёт](https://github.com/iNaturalist/SeekReactNative/blob/main/utility/badgeHelpers.ts): сравнение количества наблюдений с порогом, запись в транзакции, пересчёт после загрузки.
- [Связь с экраном](https://github.com/iNaturalist/SeekReactNative/blob/main/components/Achievements/hooks/achievementHooks.ts).

В AgroVoice сейчас `InspectionJournal.kt` сохраняет JSON и повторно использует ID
осмотра при повторном сохранении того же отчёта. Значит, нажатия «сохранить» нельзя
превращать в новые баллы. Предлагается реализация вместе с переходом журнала на
[Room](https://developer.android.com/training/data-storage/room), после A-11:

1. `AchievementDefinition`: стабильный `id`, версия правила, русское название,
   описание условия, порог, ссылка на ресурс значка. Определения — в коде/JSON assets.
2. `AchievementProgress`: `achievementId`, версия, текущий прогресс,
   `unlockedAt`, `notifiedAt`. Уникальный ключ запрещает повторную выдачу.
3. `InspectionCommitted(inspectionId)` возникает после успешного сохранения.
   Чистая функция `AchievementEvaluator` вычисляет прогресс по уникальным
   записям журнала. Для маленького журнала достаточно пересчёта SQL-запросами;
   отдельная шина событий и большой event store не нужны.
4. Осмотр и пересчёт — одна транзакция Room. Повтор того же события не увеличивает
   прогресс. Compose читает `Flow`; уведомление показывает только новую награду.
5. Для резервного копирования — отдельное событие `BackupCompleted` только после
   успешной записи архива. Нынешний JSON без фото не даёт награду за полную копию.
6. При будущем sync объединять записи по постоянным ID и пересчитывать прогресс,
   а не складывать счётчики устройств. Импорт не должен заново выдавать значки.

Предлагаемые условия, ещё не внедрены:

| ID | Название | Условие | Защита от бессмысленного накопления |
|---|---|---|---|
| `first_inspection` | Первый осмотр | Один сохранённый осмотр с существующим фото | Не за запуск камеры или инференса |
| `complete_record` | Полевая запись | Осмотр с участком, фото и заметкой | Перезапись той же карточки не новая награда |
| `follow_up` | Наблюдаю изменения | Повторный осмотр того же `plantId` в другой день | Нужна явная идентичность растения; пока её нет, правило выключено |
| `voice_workflow` | Свободные руки | Снять → услышать результат → сохранить через общий исполнитель действий | Считать завершённый сценарий, а не распознанные слова |
| `backup_created` | Данные сохранены | Успешный полный архив с фото | Действие «поделиться» без записи недостаточно |
| `review_contribution` | Помог исследованию | Эксперт подтвердил полезную правку | Не за произвольное нажатие «ошибка» |

Не выдавать баллы за количество болезней, применения препаратов, высокую
уверенность модели или ежедневную серию без пропусков. У сельского хозяйства
сезонность; сброс серии может наказывать пользователя за нормальный режим работы.
Награды не подтверждают квалификацию агронома и не разблокируют лечение.
Пользователь может отключить достижения; основная работа от них не зависит.

Проверка реализации: повторное событие, перезапуск, изменение/удаление осмотра,
импорт, два устройства, смена часового пояса, миграция правил, отключённые
уведомления и reduced motion. Для первых правил выбрать политику «полученная
награда сохраняется, текущий счётчик пересчитывается» и явно описать её в UI.
Старые данные не должны сбрасываться при добавлении нового набора значков.

обсуждает наблюдение за событиями и отделение условий наград от игровой логики.
Прочитаны вопрос и ответы через API. Это старое архитектурное обсуждение,
не актуальная инструкция по Android API. Здесь использован принцип; текст и
код ответов в проект не копировались. Конкретные транзакции/хранилище проверять
по текущей документации Android, а не по возрасту или рейтингу ответа.

Практический выбор: небольшой собственный `AchievementEvaluator` + Room + Compose.
Google Play Games и облачный сервис достижений не обязательны для локальных
значков; отдельная авторизация ухудшит сценарий автономного дипломного приложения.

## Хабр: полезная практика и её границы

Прочитано интервью [«Как с помощью машинного обучения выращивают каннабис и помидорки»](https://habr.com/ru/companies/ruvds/articles/543336/),
20.02.2021, о Fermata. Для AgroVoice полезны описанные автором работа с реальными
производителями, изменение решения после обратной связи и отдельная роль
подготовки данных. Отсюда предложение: проверить сценарий обхода с агрономом
раньше добавления сложных функций. Это интервью о чужом продукте, а не
независимое испытание нашей модели; заявления о коммерческой эффективности
не переносим в диплом как собственные результаты.

Расхождение голосового примера проверено по
[официальному SpeechRecognizer API](https://developer.android.com/reference/android/speech/SpeechRecognizer):
обычный сервис может использовать удалённое распознавание; API не предназначен
для бесконечного непрерывного слушания. Для системного on-device режима требуется
проверка доступности сервиса и языка, а для встроенного Vosk/sherpa — проверка
выбранного пакета. Внутри AgroVoice надёжнее вызывать собственные действия по ID,
чем нажимать экран через AccessibilityService. Системное управление вне приложения
— отдельное разрешение/сценарий, не обязательное условие своего hands-free UI.
