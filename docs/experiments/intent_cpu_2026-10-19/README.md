# CPU-классификатор русских команд

Обученный линейный классификатор пока **не подходит для включения в приложение**.
Это контрольный опыт против правил и исходных малых LLM, а не свободный диалог.

Модель: символьные 3/4/5-граммы, слова и признаки состояния → softmax с L2.
Словарь и классы строятся только по train; эпоха и порог уточнения выбираются по val.
Test оценивается после фиксации параметров. Аргументы входят в класс ответа:
модель не умеет создавать новые сочетания действий и значений.

Фактические результаты и длительность: [report.json](report.json).
Необработанные предложения: [predictions.json](predictions.json).
Повторная проверка этих предложений Android-протоколом и исполнителем:
[executor_report.json](executor_report.json). Исполнитель блокирует часть
небезопасных предложений, но не исправляет неверно понятые разрешённые действия.

Корпус синтетический, разделён по сценариям. Разработчики видели его раньше;
это не независимая проверка речи людей. Исходная подготовленная копия содержала
старые `Tomato/Potato/Cucumber`; актуальная копия собрана из `scenarios.json`
через `prepare_corpus.py` в отдельный каталог. Старые файлы не перезаписаны.
Trainer теперь проверяет целевые действия и аргументы перед оптимизацией.

Воспроизведение: подготовить новый каталог корпуса, затем запустить
`ml-pipeline/assistant/train_intent_classifier.py --data <корпус> --out <новый каталог> --deadline <разрешённая дата>T23:00:00+03:00`.
Исполнитель: `gradlew.bat testDebugUnitTest --tests *RulesBaselineTest`.
Обучение требует новой команды Бориса в день запуска; веса остаются в `runs/`.
