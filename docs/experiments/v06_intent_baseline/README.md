LLM: системный промпт и состояние из `prepare_corpus.py`, ответ ограничен JSON-схемой протокола, temperature 0; сбор — `ml-pipeline/assistant/run_ollama_router.py --model <model>` через локальный Ollama 0.31.1, оценка — тот же тест (`localLlmAnswers`): ответ проходит `AssistantProtocol` (форма, диктовка, отрицания) и `ActionPolicy`. Медианная задержка на ПК разработки — в отчётах; это не замер телефона.

Как понимать:

- Точные фразы безопасны, но не понимают ни одной перефразировки корпуса. В режиме грамматики Vosk такие фразы и не будут распознаны.
- `FreeSpeech` написан при видимых всех частях корпуса, поэтому его числа — проверка разработки, **не независимый тест** и не точность на людях. Отдельные свежие фразы в `FreeSpeechTest` сразу нашли две ошибки обобщения («двадцать первый», повтор шага) — ожидать, что на живой речи результат будет ниже.
- Ошибки распознавания Vosk без грамматики сюда не входят. Режим «Свободная речь» в приложении экспериментальный и выключен по умолчанию.
- Малые LLM без дообучения для управления непригодны: Qwen3-0.6B почти всегда выбирает случайное действие (часто CROP), Qwen3.5-0.8B почти всегда отказывается или уточняет. Исполнитель остановил часть опасных предложений (у Qwen3-0.6B 23 из 45), но пропускает допустимые в состоянии, хотя неверные действия — поэтому одной проверки состояния мало. Дообучение (V-07) нужно сравнивать с этой точкой и с `FreeSpeech`.
- Intent-классификатор **не сравнивался**: его обучение на домашнем ПК требует команды Бориса. Независимый набор фраз и говорящих — V-05/V-08.
