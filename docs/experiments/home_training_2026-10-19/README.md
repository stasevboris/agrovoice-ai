# Домашние пилоты: AMD и CPU

RX 9060 XT использована через ROCm в WSL; CPU — для intent baseline, оценки и
ONNX Runtime. Это ограниченные эксперименты, новые веса в APK не включены.
Исходные чекпойнты и логи сохранены в `runs/home_20261019_*`; компактные результаты
находятся рядом с этим документом. Неудачные первые попытки также сохранены.

## Зрение

Одинаковая пара YOLO26n: 20 эпох, 416, batch 16, FP32, seed 20261019,
train против train с просмотренными негативами. Выбор по field-val, без test.
Сравнение ниже относится к **обычной голове для Android**, а не end-to-end голове
из стандартной оценки Ultralytics. Источник — [detector_evaluation.json](detector_evaluation.json).

| Проверка | Без негативов | С негативами |
|---|---:|---:|
| Field-val mAP50–95 | 0.28773 | 0.28713 |
| Срабатывания на предметах при пороге 0.25 | 2/5 | 2/5 |
| На неизвестной фасоли | 112/133 | 114/133 |
| На сценах DeepWeeds с неизвестными видами | 1184/1581 | 429/1581 |

Негативы помогли на одном источнике, но отказ на неизвестном растении не решён.
DeepWeeds — proxy по сценам источника: фон не полностью размечен. Набор предметов
слишком мал для надёжного вывода. В train отсутствуют классы 7, 13, 14; это не
полный релиз taxonomy_v1. Ограничения источников, почти-дубликатов и lab-перекоса
сохраняются. ONNX `[1,53,3549]` экспортированы локально; численная PyTorch/ORT
проверка и SHA записаны в том же отчёте. Порог не подбирался на test.

MobileNetV3-small: замороженный ImageNet backbone и линейная голова,
20 эпох. На **GT-вырезках** field accuracy 0.57601, macro-F1 0.48179;
lab accuracy 0.93795, macro-F1 0.87351 ([отчёт](mobilenet_report.json)). Это не
полная цепочка камеры и не прямая альтернатива detector mAP. Права на исходные
ImageNet-веса требуют проверки перед распространением.

## Русский помощник

Qwen3-0.6B, revision `c1899de289a04d12100db370d81485cdf75e47ca`, Apache-2.0.
FP32 LoRA r8 q/v, assistant-only loss, без обрезки состояния или ответа.
Третья эпоха выбрана по val; train/val/test — 138/24/39 синтетических примеров.
Исходная HF-модель выдала нестрогий JSON во всех test-примерах, преимущественно
из-за Markdown-ограждений. Это не нулевое понимание и не сопоставимо напрямую с
прежним Ollama constrained decoding.

После SFT: 16/39 точных решений, 9 правильных выполнений, 5 лишних предложений
действия, 0 невалидных JSON ([qwen_report.json](qwen_report.json)). Через тот же
Android-протокол и исполнитель: 9/20 точных действий, 3 неправильных разрешённых
действия, 8 без действия; 19/19 запретных примеров не исполняются
([qwen_executor_trained.json](qwen_executor_trained.json)). Исполнитель отсёк
лишние raw-предложения на этой синтетике, но ошибки выбора остаются.
Модель не пригодна для управления приложением: не квантована, не проверена на
телефоне или независимой речи. Корпус заморожен до новых команд выбора карточек
справочника и не покрывает их. Test не использовался для дообучения.

CPU-классификатор — [отдельный отчёт](../intent_cpu_2026-10-19/README.md).

## Воспроизводимость и ограничения ресурсов

Тренеры запускаются через `train_home_pilot.py` с явным дедлайном и отдельной
группой процессов. Окно не переносится на следующий день. Версии и параметры —
`qwen_environment.json`, `qwen_input.json`, `*_benchmark.json`, исходный
`runs/home_20261019_pilot/environment.json`; метрики — JSON/CSV рядом.
Начальные MobileNet/Qwen завершились errno 12 при конкурентной оценке на CPU
([initial_failures.json](initial_failures.json)). У evaluator ограничен размер
самого списка картинок, последующие задачи запускались последовательно и прошли.
Системные лимиты RAM и драйверы не менялись. Проверки кода — [verification_final.json](verification_final.json).
