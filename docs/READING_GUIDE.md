## Что показал аудит

Аудит охватывает актуальные входные документы и их локальные ссылки, а также
согласованность ключевых утверждений с манифестом и текущими скриптами. Это не
перепроверка каждого исторического эксперимента и не повторный аудит всего кода.
Машинная проверка ссылок и область охвата —
[отчёт](../artifacts/verification/discovery_20261019/documentation_report.json).

| Проблема | Как читать / что исправлено |
|---|---|
| Целевые классы путаются с поддержкой APK | Поддержку проверять по STATUS и manifest; taxonomy/ROADMAP описывают цель |
| D-02 в ROADMAP называл сорняки негативами «не лист» | Исправлено: видимые неизвестные листья — отдельные положительные растения/unknown, не пустые рамки |
| M-04 предлагал принимать решение по test | Исправлено: выбор по field-val; test после фиксации, исторический PlantDoc не независимый приёмочный набор |
| Старый GPU README даёт ориентиры времени и привязку к понедельнику | Считать это старым baseline-рецептом. Заголовки привязаны к сеансу; длительность надо измерить, обещания «успеют» заменены условной оценкой |
| Основной `data.yaml` строгого набора валидируется на field+lab | Для новой пары добавлен конфигуратор field-only val. Старый mixed-val не выдаётся за тот же критерий |
| Старый train_queue оценивает test после каждого запуска | Сохранён для baseline, ограничение вынесено в PLAYBOOK. Новый пилот не включает test в конфиг и не использует старую очередь |
| Исследовательская рекомендация звучит как окончательный выбор | D-FINE/DINO/Qwen — кандидаты для опыта. Сейчас нет результата обучения, доказывающего их превосходство |
| Метаданные источника принимают за разметку | Вид iNaturalist не означает здоровье; рамки OPTIMA не целые листья; условия и назначения записаны отдельно |
| Корневой PROJECT_GUIDE больше не существует | Читать [историческую копию](history/PROJECT_GUIDE_until_2026-10-16.md) только для истории, текущий вход — полный отчёт |
| Архивные статьи/отчёты содержат устаревшие очереди | Даты 3–5 октября и `docs/history/` — история; они не переопределяют STATUS и новый протокол |

Старый [аудит 16 октября](AUDIT_AND_PLAN_2026-10-16.md) нужен для обоснований,
а [отчёты 4 октября](reports/README.md) — для происхождения ранних результатов.
Документы `docs/thesis/2026-10-05/` — снимки записки, не текущая спецификация.
Числа из исходной темы, которые не подтверждены файлами испытаний, не переносить
в презентацию как достигнутые показатели.

## Что понимать перед защитой

Нужно уметь своими словами объяснить: зачем офлайн; что делает детектор; чем
score отличается от вероятности болезни; почему field важнее lab; как отделены
train/val/test; когда приложение отказывается; кто подтверждает лечение; как
проверяли голос и скорость. Новые достижения — приятная функция интерфейса,
но качество диплома определяется проверяемой основной цепочкой и честными опытами.
