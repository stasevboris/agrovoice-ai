полный список документации для продолжения разработки. Критерии: ясный вход,

проверяемые выводы и приоритеты. Аудит выполнен по прямому запросу Бориса;
обычное правило выбирать рабочую карточку вместо нового аудита здесь не определяет объём.

## Главный вывод

Есть собираемый локальный Android-прототип: камера/галерея, ONNX-распознавание,
русские голосовые команды, системная офлайн-озвучка при наличии голоса и JSON-журнал.
Подготовлены данные, рецепты обучения и исследовательская база.
Готовность к надёжной полевой диагностике, полному управлению обычной русской речью
и выдаче проверенных рекомендаций пока не подтверждена.

Следующий результат должен быть рабочим инкрементом. Независимо от GPU можно
реализовать V-06 — общий исполнитель действий; параллельное организационное условие
качества зрения — собственные независимые сценарии R-01. GPU-пилот начинать по
[PLAYBOOK](../guides/TRAINING_PLAYBOOK.md), не с массового запуска всех кандидатов.

## Данные, исследования и достоверность выводов

Подготовка vision/unknown/ASR/intents подтверждается сохранёнными отчётами и
тестами преобразований. Их нельзя считать обученными моделями. Строгий отбор
геометрии исключает часть классов, но не создаёт новых экспертных диагнозов.
Open Images — небольшой просмотренный пилот; исходный автоматический набор не принят.
Beans после exposure уже не «совершенно новый вид» для test; у DeepWeeds нет меток болезней.
Состояние iNaturalist неизвестно; OPTIMA размечает другую геометрию, не целый больной лист.
Подробности — [данные](../data/README.md), [веб-пополнение](../data/WEB_DATA_2026-10-19.md).

FLEURS — общая читаемая речь, MASSIVE — сторонние намерения, синтетические сценарии
AgroVoice — регрессия/начальный SFT. Ни один из этих фактов не доказывает качество
полного голосового обхода с независимыми пользователями.

D-FINE/DINOv2/Qwen и другие кандидаты — гипотезы для сравнения. Выбор следует делать
по полной цепочке, полевому риску, отказам, памяти и задержке на телефоне.
Рекламные метрики разных наборов, качество GT-вырезок и скорость GPU не заменяют это сравнение.

Первичные источники в исследовательских каталогах полезнее вторичных пересказов,
но ссылка не даёт права копировать книгу или распространять веса. Внешние условия
при этом аудите заново не проверялись. Перед фактическим использованием требуется
проверка конкретной редакции/ревизии и её лицензии; агрономические дозировки —
только подтверждённый Госреестр РБ и статус draft до специалиста.

Исторические значения качества и скорости сохранены в
[техническом отчёте, разделы 8–10](../architecture/PROJECT_REPORT_2026-10-19.md).
Они не пересчитаны на новых весах. Исходные показатели темы без файла испытаний
не должны переходить в выводы диплома.

## Проверки и практические ограничения

Команды запускались из корня, кроме Gradle — из `android-app`:

```powershell
.\ml-pipeline\venv\Scripts\python.exe -X utf8 -m unittest discover -s ml-pipeline/tests
.\ml-pipeline\venv\Scripts\python.exe -X utf8 android-app/fetch_assets.py --check
.\ml-pipeline\venv\Scripts\python.exe -X utf8 -m pip check
# Из android-app
.\gradlew.bat testDebugUnitTest assembleDebug assembleDebugAndroidTest lintDebug
```

Python: 75 тестов успешно; JVM XML: 36 тестов без ошибок. Gradle подтвердил
актуальность тестов и APK (`UP-TO-DATE`), lint выполнился и завершился успешно:
58 предупреждений и 2 подсказки, ошибок нет. `pip check` не нашёл конфликтов,
SHA-проверка всех локальных модельных/голосовых ассетов прошла.
Источник чисел — [report.json](PROJECT_AUDIT_2026-10-19.report.json).
Итог после изменений путей и проверка документации также записаны там.
Упаковщик дополнения запущен в отдельной временной рабочей папке с пустыми
синтетическими наборами и настоящими документами: ZIP/CRC и включение PLAYBOOK
по новому пути проверены. Исходные большие архивы не пересоздавались.

Это не новая приёмка телефона: инструментальные тесты только собраны, телефон
не использован. Не проводились GPU-обучение, полная пересборка наборов, повторный
просмотр всех изображений, свежий benchmark, установка ПО или публикация.
Тесты на существующем ПК и `pip check` не подтверждают чистую установку без локальных файлов.

Существующие тесты покрывают ряд преобразований данных, классы/геометрию,
загрузку/релиз, голосовой parser и формулировки результата. Критичные недостающие
проверки привязаны к карточкам: миграция/восстановление журнала, независимый OOD,
свободный русский цикл, гарнитура/доступность и итоговый телефонный паритет новых весов.

## Следующие рабочие результаты

1. V-06: один общий исполнитель действий, тесты контекста/отмены/повторов, первый сценарий кнопки и голоса через него.
2. R-01: протокол собственных фото/речи и независимых split; Борис обеспечивает съёмку и подтверждение меток.
3. Исправление недостающих классов для полного релиза; ограниченный парный GPU-пилот по PLAYBOOK допускается с явным указанием неполноты.

5. После измеренного выбора — A-01/A-02/A-03, лицензированный field-релиз, паритет и реальные испытания Note 7/A56.

Для финального выбора потребуются бюджет аренды, допустимая задержка/память,
доступность агронома и полевых данных. Пока это неопределённости, а не основание
назначать победителя по внешнему рейтингу.
