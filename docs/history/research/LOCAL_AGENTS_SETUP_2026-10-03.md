# Локальный агент для базовых задач

Проверено 3 октября 2026 года. Модель генерирует ответы, LM Studio/Ollama исполняет модель и предоставляет API, агент читает файлы, применяет изменения и запускает команды. Для Бориса первым пробуем **LM Studio + Qwen3.5-9B Q4_K_M + OpenCode**; для работы внутри VS Code альтернативой будет Cline. Это предложенная конфигурация: ничего из перечисленного в этой сессии не установлено и не запущено.

## Какие агенты найдены

| Инструмент и первичная документация | Работа локально | Когда выбрать |
|---|---|---|
| [OpenCode V2](https://opencode.ai/v2/docs/providers) | Обнаруживает локальные LM Studio/Ollama/vLLM, работа по репозиторию, инструменты/команды, [настройка разрешений](https://opencode.ai/v2/docs/permissions) | Основной кандидат без привязки к IDE. **V1 и V2 имеют разные поля конфигурации**, сверить установленную версию |
| [Cline](https://docs.cline.bot/running-models-locally/overview) | Выбор LM Studio/Ollama в настройках, чтение/правки/terminal, компактный prompt для локальных моделей | Удобно видеть diff и ход задачи в VS Code. Для первого запуска включить Use Compact Prompt и выбрать именно локальный provider |
| [Continue](https://docs.continue.dev/customize/model-providers/top-level/lmstudio) | LM Studio provider, Chat/Edit/Agent; [tool_use требуется Agent mode](https://docs.continue.dev/customize/deep-dives/model-capabilities) | Хорош для помощи в редакторе и небольших правок. Возможность чата/дополнений в конкретной IDE не означает одинаковую поддержку всех агентных функций; основной пример ниже для VS Code |
| [Aider](https://aider.chat/docs/llms/openai-compat.html) | CLI, локальный API, работа с выбранными файлами и Git | Для ограниченной задачи «измени эти 1–3 файла». Уместно проверить Qwen2.5-Coder-14B; меньшие модели иногда неправильно возвращают формат diff |
| [OpenHands](https://docs.openhands.dev/openhands/usage/llms/local-llms) | Локальные модели и backend, контейнеры/Agent Canvas | На позднее: документация рекомендует контекст от ~22k и более крупную модель с 24 ГБ VRAM. Это не минимум для любого агента, но наш 16 ГБ компьютер ограничивает именно такой сценарий |

**Roo Code не рекомендую как новую основную установку:** официальный репозиторий [архивирован 15 мая 2026 года](https://github.com/RooCodeInc/Roo-Code), README сообщает о закрытии расширения. Существуют форки, но их поддержку/совместимость нужно оценивать отдельно. Не переносить старые рейтинги 2025 года без проверки состояния проекта.

Все эти агенты могут пользоваться и облачными провайдерами; наличие слова local не заставляет каждый сетевой компонент работать автономно. Для локального инференса выбрать localhost provider, не подключать cloud fallback. Для строгого офлайна дополнительно проверить telemetry, удалённую индексацию/embeddings, MCP, web tools и обновления конкретного клиента. Первоначальная загрузка весов и установка требуют интернета.

## 1. Подготовить модель и локальный API

Сначала закончить study10_v2: параллельный LLM будет конкурировать с YOLO за GPU/VRAM. Выбор весов и размеров — в [обзоре моделей](LOCAL_CODING_MODELS_2026-10-03.md).

1. Установить LM Studio из официального источника, выбрать актуальный llama.cpp Vulkan runtime и RX 9060 XT. Загрузить одну Qwen3.5-9B Q4_K_M; начать с 8192 токенов/одной сессии. После проверки VRAM можно увеличить контекст до 16k.
2. Во вкладке Developer включить локальный сервер. Оставить loopback `127.0.0.1`, порт 1234. Записать **Model API Identifier** выбранной модели.
3. В PowerShell проверить сервер:

```powershell
$taskLocalModels = Invoke-RestMethod -Uri 'http://127.0.0.1:1234/v1/models'
$taskLocalModels.data | Select-Object id
```

Результат должен содержать ID нужной локальной модели. Если вместо списка ошибка подключения — исправлять сервер, а не получать платный ключ облачного API. Если сервер настроен с API-key authentication, передать установленный локальный ключ в клиент; слово `local` ниже является лишь примером для сервера без проверки ключа.

4. Проверить маленькое задание с одним чтением файла и одной правкой. Важен фактический корректный tool call, а не текст «сейчас отредактирую». Установка `tool_use` в конфиге объявляет способность и **не добавляет её** модели или parser.

## 2. OpenCode — пример для V2

Шаблон: [opencode-v2-lmstudio.example.json](config_examples/opencode-v2-lmstudio.example.json). Он хранится среди документов и **не активирован** в рабочем проекте. Заменить `REPLACE_WITH_LOCAL_MODEL_ID`, сохранить как `opencode.json` в рабочей копии проекта. При установленной V1 этот шаблон не подходит: ориентироваться на её документацию или явно установить V2.

В V2 поля называются `providers`, `settings.baseURL`, `permissions`, действие shell — `shell`. В V1 используются другие имена. Локальный provider LM Studio обнаруживает модели через свой API; выбрать её из списка моделей клиента. [Источник конфигурации](https://opencode.ai/v2/docs/providers).

В образце чтение/обычный `git status` и `git diff` разрешены, запись в `docs/agent-output/*` разрешена; остальные изменения и команды требуют решения в клиенте. Три файла протокола и текущая выборка запрещены для правок, запуск подагентов выключен, push запрещён. Так первую задачу по документу можно выполнить без подтверждения каждого абзаца. Под свои повторяющиеся задания разрешать **конкретные** команды/каталоги после проверки. Сопоставление правил и их порядок описаны [здесь](https://opencode.ai/v2/docs/permissions).

Правила агента не являются изоляцией операционной системы: разрешённая shell-команда может сделать больше, чем следует из её имени, а правила выбранного встроенного/кастомного агента могут добавляться после глобальных. Для самостоятельных правок кода лучше дать отдельную копию Git-репозитория без датасетов, WSL-диска, keystore и тяжёлых весов; после задачи посмотреть diff и перенести изменение. Не запускать стороннего агента по изменяемым файлам активного сравнения YOLO.

Поле `share: disabled` указано явно; текущая [V2-документация конфигурации](https://opencode.ai/v2/docs/config) сообщает, что session sharing ещё не поддерживается. Это не доказательство отключения любой другой сетевой функции.

## 3. Cline — альтернатива в редакторе

Установить расширение Cline из официального marketplace, открыть Settings → provider **LM Studio**, Base URL `http://127.0.0.1:1234` (родной provider Cline, без `/v1`), выбрать модель в списке. Включить **Use Compact Prompt**. Для общего OpenAI-compatible provider URL уже должен включать `/v1`; не смешивать эти два способа настройки. [Текущая инструкция Cline](https://docs.cline.bot/running-models-locally/overview).

Начать с документации/одного файла и просмотром diff. Для повторяющейся базовой задачи разрешать чтение и правки рабочей копии; команды, установки и внешние действия добавлять по мере нужды. Автоматическое выполнение десятков шагов маленькой моделью не гарантирует правильный результат.

## 4. Continue — готовый YAML-пример

[continue-lmstudio.example.yaml](config_examples/continue-lmstudio.example.yaml) содержит provider `lmstudio`, роли `chat/edit/apply`, localhost API, 8k context, 2048 max output. В локальной конфигурации Continue заменить Model API Identifier. На Windows типичный глобальный файл — `C:\Users\Boris\.continue\config.yaml`; существующий конфиг сначала сохранить, затем выбрать/добавить новую конфигурацию через настройки расширения. Это пример для текущего YAML schema v1, а не старого config.json. [Provider](https://docs.continue.dev/customize/model-providers/top-level/lmstudio), [справочник YAML](https://docs.continue.dev/reference).

Не использовать основную 9B chat-модель как постоянно загруженный autocomplete без отдельной проверки. При потребности в дополнении кода можно отдельно оценить маленький coder, но две одновременно загруженные модели отнимают память друг у друга. Для первого агентного опыта достаточно одной.

## 5. Aider — ограниченная CLI-задача

После отдельной установки Aider, в **новом PowerShell-окне** и копии репозитория:

```powershell
$env:OPENAI_API_BASE = 'http://127.0.0.1:1234/v1'
$env:OPENAI_API_KEY = 'local'
aider --model 'openai/REPLACE_WITH_LOCAL_MODEL_ID' --no-auto-commits --no-analytics --no-check-update
```

Переменные действуют только в этом окне, не меняют настройки Codex и не означают использование облачной OpenAI-модели. Заменить ID, добавить только нужные файлы. `--no-auto-commits` оставляет изменения для просмотра; commit выполнить после проверки. При настоящем локальном API-key authentication вместо `local` указать его ключ. [Совместимый API](https://aider.chat/docs/llms/openai-compat.html), [параметры](https://aider.chat/docs/config/options.html).

## Какие задачи ему отдавать

Готовый первый prompt: [local-agent-task.example.md](config_examples/local-agent-task.example.md). Он создаёт один сводный документ по существующим результатам и требует ссылку на ключ исходного JSON у каждого числа.

Затем подходящие задачи: перевод ресурсов интерфейса, отдельный Compose-компонент, небольшая Python-утилита, обновление README по фактам, поиск причины ошибки сборки. У задания должны быть конкретные входные файлы, разрешённый результат, критерий готовности и нужная проверка. Например: «исправь перенос текста в этом компоненте; собери debug APK; покажи diff; не меняй Gradle-зависимости и протокол обучения».

Удобнее ограничить один запуск одной маленькой задачей. Принимаем результат по diff/сборке/проверяемому поведению, а не по уверенной фразе агента «всё готово». Обучение модели, её оценка и публикация APK остаются отдельными процессами с собственными журналами.
