# Новые веб-фотографии и OPTIMA: назначение и расположение

Поручение Бориса — искать также обычные фото и готовить найденное к обучению.
Итоговые числа ниже из [отчёта подготовки](WEB_RESEARCH_PREPARATION_REPORT.json).
Это дополнение к [ранее подготовленным данным](TRAINING_PREPARATION_REPORT.json),
не замена основного набора и не результат обучения модели.

## Что подготовлено

| Набор | Фактический результат | Что можно делать |
|---|---|---|
| `ml-pipeline/dataset_web_leaf_presence_v1/` | Из 15 обычных фото принято 11, исключено 4; подготовлены 3 производные вырезки | `train.jsonl`: положительные сцены с листьями для gate; `crops.jsonl`: отдельные выбранные листья для species/unknown. Только train |
| `ml-pipeline/dataset_optima_rgb_v1/` | Из 90 RGB-кандидатов принято 88; 283 исходные рамки областей поражения; 2 похожих изображения исключены | `train.jsonl`: вспомогательное обучение представлений; `source_task_train_coco.json`: отдельная исходная задача областей болезни |

В сумме принято **99 новых исходных изображений**; три вырезки не увеличивают
число наблюдений. Это небольшой проверенный инкремент, а не массовый независимый
тест. Ни один новый снимок не объявлен автоматически подтверждённым здоровым
листом. Пробелы строгого 49-классового train этим дополнением не закрыты.

## Обычные фото: откуда метки

Источник — публичные наблюдения iNaturalist с исходным статусом research grade,
фото только CC BY или CC0. Вид сохранён из источника; этот статус не подтверждает
здоровье растения. Авторы, URL, ID, дата, лицензия и SHA256:
[web_photo_sources_v1.json](../../ml-pipeline/external/web_photo_sources_v1.json).
Решения ассистента:
[web_photo_review_v1.json](../../ml-pipeline/external/web_photo_review_v1.json).

Просмотрены контактные листы всей выборки и отдельные изображения для выбранных
рамок. Размечено **наличие видимого листа**, а не диагноз. Ствол дерева, жёлуди,
кадр с доминирующим цветком и плод огурца исключены из листового пилота; они не
превратились в негативы «нет растения». Частичные рамки не описывают все листья
сцены: применять их как полную YOLO-разметку нельзя.

Клён, крапива и дуб вне taxonomy_v1. Отдельные вырезки клёна/дуба пригодны для
unknown-crop train; огуречная вырезка — только для вида, `disease_label=null`.
Не смешивать задачу определения культуры с определением болезни.

Использована публичная версия medium, а не оригинал камеры. Все добавления
train-only, собственного val/test не создавали. Группы автора/даты сохранены;
при дальнейшем расширении не разводить фото одного наблюдения по split.
Проверены pHash-повороты/отражения против существующего индекса исходников и
внутри пилота. Это не доказывает отсутствие всех веб-дубликатов.

Кандидаты Wikimedia Commons сохранены в
`artifacts/verification/discovery_20261019/sources.json`; сервер изображений
вернул HTTP 429, поэтому они не включены в обучение. Название файла Commons
также не считается экспертным диагнозом. Фото с непроверенной лицензией не взяты.

## OPTIMA: почему отдельная папка

Wageningen University & Research, [запись v1](https://doi.org/10.5281/zenodo.6778647),
CC BY 4.0. Полевая съёмка яблони, моркови и винограда; источник указывает Испанию,
Францию и Италию. Подготовлены только RGB; multispectral к Android RGB не примешан.
Метаданные и исходные имена сохранены. Для группировки использованы даты из имён;
они не доказывают независимость растений/участков. В именах винограда есть также
дата `21_08_23`, хотя краткое описание записи перечисляет июль: это расхождение
нельзя скрывать или переименовывать без подтверждения авторов.

На момент проверки существует [v2, запись 8339572](https://doi.org/10.5281/zenodo.8339572).
Для ограниченного пилота закреплён меньший исторический v1; v2 не скачан и
не объявлен подготовленным. Его нельзя позднее считать независимым от v1.

Исходные классы: `apple_applescab`, `carrot_alternaria`, `grape_downymildew`.
Исходный class 0 внутри каждой папки сохранён в `native_labels/`; в отдельном
COCO созданы три категории этой задачи. **Это не taxonomy_v1.** Рамки обозначают
области болезни, не целые листья; морковь и это состояние винограда не становятся
новыми классами APK. Масштаб/геометрия проверены скриптом, диагнозы взяты из
источника, не переопределены ассистентом. Превью показывает сложный фон и свет,
но полный экспертный пересмотр всех рамок не проводился.

Файлы изображений, исключённых по похожести, оставлены на диске для прослеживаемости.
Обучать только по `train.jsonl` / COCO, не по слепому обходу каталога `images/`.
Отдельного независимого test здесь нет. Использование как вспомогательного
train допустимо в собственном ограниченном опыте; эффект ещё нужно измерить.

## Воспроизведение и передача на GPU

Из корня проекта, существующее Python-окружение и индекс исходников:

```powershell
.\ml-pipeline\venv\Scripts\python.exe -X utf8 ml-pipeline/external/prepare_web_photos.py
.\ml-pipeline\venv\Scripts\python.exe -X utf8 ml-pipeline/external/prepare_optima.py
.\ml-pipeline\venv\Scripts\python.exe -X utf8 ml-pipeline/gpu_kit/alternatives/pack_discovery_addon.py
```

Команды подготовки требуют нового выходного каталога и не перезаписывают старые
данные. Для повторной проверки можно передать `--out` с новым именем внутри
`ml-pipeline/dataset*/`. Нужный индекс:
`ml-pipeline/.cache/external/hash_index/current_sources.npy`; его воспроизведение
описано в [hash_index.py](../../ml-pipeline/external/hash_index.py).
Сборщики требуют зависимости существующего venv; это не автономные файлы stdlib.

Дополнение упаковано отдельно:
`artifacts/gpu_kit/agrovoice_discovery_addon_20261019.zip`;
[состав, SHA256, CRC](../../artifacts/gpu_kit/agrovoice_discovery_addon_20261019.report.json).
В архив входят только принятые изображения, выбранные вырезки, исходные подписи,
метаданные и инструкции. Архив не содержит обученных весов.
Как выбрать опыт и число запусков — [TRAINING_PLAYBOOK](../guides/TRAINING_PLAYBOOK.md).
