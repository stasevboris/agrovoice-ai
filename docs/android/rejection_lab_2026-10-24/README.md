# Экспериментальный Android-путь S → DINO → отказ

Lab-сборка умеет применять фиксированный crop-verifier после новой S.
Это перенос проверенного на ПК кандидата, а не подтверждение его качества
в камере телефона. На устройстве полная цепочка пока не проверена:
Redmi отсутствовал в ADB. [Проверки и ограничения](report.json).

## Поведение

- Сначала выбирается общий класс-победитель S, затем применяется выбор культуры.
  Ручной выбор не превращает другой лист в заболевание выбранной культуры.
- Детектор работает с фиксированным порогом из эксперимента. Verifier сравнивает
  logit культуры S с reject; он только удаляет ответ, не меняет диагноз и confidence S.
- Проверяются первые восемь предложений после NMS и фильтра культуры. Остальные
  не получают диагноз; экран, голос и JSON отдельно сообщают число пропусков.
  Лимит отличается от desktop-оценки всех предложений: прежние метрики нельзя
  автоматически переносить на Android.
- Ошибка загрузки/verifier прерывает анализ; обход проверки и выдача непроверенных
  предложений S не предусмотрены. Отказ не различает предмет, неизвестную культуру,
  плохой кадр и ошибку проверяющего модуля. Правильность болезни им не проверена.
- В отчёте и черновике сохраняются решения, исходные рамки, параметры и SHA обоих
  графов. Обновления через сервер пока не поддерживают такие составные модели.

## Локальная сборка

Данные и веса остаются приватными. Обычная сборка не требует экспериментальных
весов. Сначала из корня репозитория подготовить отдельную новую папку:

```powershell
.\ml-pipeline\venv\Scripts\python.exe -X utf8 android-app/prepare_rejection_lab.py `
  --detector-run runs/home_20261023_collected/runs/home_20261023_allcrops_web_v1_yolo26s_416_s20261003 `
  --study runs/rejection_improvement_20261024 `
  --data ml-pipeline/dataset_rejection_v1 `
  --out artifacts/gpu_kit/rejection_lab_20261024
```

Папка уже создана в этой рабочей копии; повторно создавать её не нужно.
Сборщик сверяет фиксированный выбор по calibration, SHA графов и связь verifier
с исходной S. Обучаемая сейчас S с другим seed этим комплектом не подменяется.

```powershell
Set-Location android-app
.\gradlew.bat assembleLabDebug `
  -PrejectionExperimentDir=F:/agrovoice-ai/artifacts/gpu_kit/rejection_lab_20261024
```

Выбрать модель «S + DINO: эксперимент отказа». Порог детектора в этом режиме
фиксирован; slider его не меняет. Для изолированной телефонной проверки добавить
`-PisolateApp=true`; пакет будет `com.agronomy.phytomonitor.lab.verification`.
Перед обновлением существующей установки проверить её резервную копию.
Не использовать `connectedDebugAndroidTest`, удаление приложения или очистку данных.

## Проверки и продолжение

JVM проверяет правило отказа, глобальный выбор класса, ограничение числа вырезок,
сохранение отчёта/черновика и запрет составных серверных обновлений. Python проверяет
сборку приватного комплекта и его исключение из field. В обоих flavor выполнены
JVM-тесты, сборка и lint; команды и результаты находятся в report.json.

Предобработка: floor/ceil crop без отступа → bilinear pad gray114 → JPEG95 → RGB
NCHW с ImageNet mean/std. Изменение размеров воспроизводит расширенный bilinear
kernel Pillow при уменьшении. На двух синтетических изображениях сравнивались
входные тензоры Android через Robolectric native и Python/Pillow; небольшое
расхождение сохранено в отчёте. Это не проверка камеры или качества модели.

Дальше на изолированной установке: проверить реальные вырезки и решения против
desktop, сохранение/восстановление осмотра, полный путь камеры и задержки для
одного и нескольких листьев. При расхождениях не подбирать порог по уже просмотренным
audit/test. Рабочую field-модель до этих проверок не заменять.
