Нижняя карточка получила отдельные строки кнопок сравнения и чтения, чтобы они не теснились наNote7. Диалог заметки и журнал прокручиваются. Статус доступности/ошибки TTS виден в карточке; ошибки callback не скрываются под сообщением об успешном чтении.

Микрофонные callback теперь переводят обновления Compose и действия на главный Android-поток. Диктовка может запросить стандартное разрешение микрофона при первом использовании; кнопка остановки переводит заметку к голосовому подтверждению. В фоне диктовка выключается.

## Проверки и доказательства

Профиль `yolo26s_final_v15_phone` содержит отдельные142синтезированныхWAV, подготовленные с `-IncludeLab`, и новые native-сценарии. Gradle unit-check и компиляция instrumentation прошли. Финальные native/parity/десять серий bitmap-скорости должны завершиться с настоящими доказательствами; наличие установки не подменяет их.

`NoteSpeechFlowTest` открывает реальные микрофонные сессии. Затем настоящий AndroidVosk декодирует заранее сохранённыеPCM/WAV двух голосов, результат поступает в production callback активного режима: фраза камеры остаётся текстом, заметка завершается, «подтвердить» сохраняет её. Проверяется остановка в фоне. WAV не воспроизводятся в микрофон: это проверка интеграции/контекста/движка и жизни микрофона, **не сквозной акустический тест речи людей**. Такие полевые проверки Борис сможет провести утром.

Для TTS фактически установлен русский голос `ru-RU-language`; получен настоящий `onDone` при volume0. Микрофон остановлен на время запроса; чтение и микрофон прекращены в фоне. В `tts_flow.json` сохраняются фактические голос/callback/режим проверки. Звук ночью не воспроизводился, качество динамика не заявляется.

Журнал проверяется на связи с точным исходнымprediction/модельюSHA, сохранении участка/оценки после чтения с диска, отсутствии дубликата, комбинированном поиске/фильтре и реальной записи через contentURI с обратным чтением JSON. Собственные тестовые записи и файлы удаляются по новымID; пользовательские данные не удаляются. Системный файловый выбор всё равно требует действий пользователя.

## Стек и хранение

Новые библиотеки не добавлены. Kotlin/Compose, прежнийVosk small-ru-0.22, системныйAndroidTTS, ONNXRuntime. Основные записи — JSON в app-external `inspections`; сырыеprediction — `results`, фото — `photos`. Journal-JSON обратно совместим: у старой записи без `plot` пустое название. Экспорт через AndroidStorageAccessFramework/CreateDocument. Нет новыхInternet/GPS-разрешений, облачного ASR, сервера или автоматического обучения на пользовательских оценках.

Источники возможностей: [AndroidTTS](https://developer.android.com/reference/android/speech/tts/TextToSpeech), [AndroidStorageAccessFramework](https://developer.android.com/training/data-storage/shared/documents-files), [Vosk](https://alphacephei.com/vosk/). Это происхождение применяемыхAPI; результаты конкретногоNote7 подтверждаются локальнымиJSON.

## Сохранённый первый отказ0.14

В0.14 прошли9/10native-тестов; новыйNoteSpeechFlowTest остановился на подтверждении. Причина перехода: noteReviewVoice переключался до асинхронного освобождения прежней диктовочной сессии. Слишком быстрое «подтвердить» ещё попадало в режимnote, а неnote_review. Теперь callback завершения диктовки вызывается только после освобождения еёNativeResources и active=false; новая сессия затем использует отдельнуюграмматику.0.14/еёinstrumentation/142WAV сохранены как неудачный этап, не объявлены провереннымAPK.0.15 получила отдельнуюпапку и новые реальныепроверки. WAV не редактировались ради этой ошибки.
