# Записанная русская речь: проверка Vosk

Проверка на Redmi Note 7 выполнена; исходные гипотезы, выборка и числа —
в [report.json](report.json). На выбранных записях свободная диктовка дала
52 ошибки на 220 эталонных слов (WER 0,2364). Ограниченная командная грамматика
дала 214 ошибок на те же 220 слов; она не предназначена для расшифровки
обычного связного текста. Эти числа не являются WER голосовых команд в поле.

В одном сегменте командная грамматика получила «добавь кадр» из постороннего
текста; декодер пропустил `ADD_FRAME`. Действие не исполнялось. Это наблюдение
о возможном ложном распознавании при непрерывном слушании, а не измеренная
частота ошибочных действий приложения. В одноразовом режиме контроллер
завершает слушание раньше, на первой непустой гипотезе этой записи.
Порог не менялся по этой выборке; для выбора режима и порога нужны записи
настоящих команд вместе с посторонней речью.

Протокол использует готовый `dataset_asr_ru_fleurs_v1`, без скачивания и обучения.
Источник — [Google FLEURS, ru_ru](https://huggingface.co/datasets/google/fleurs),
лицензия CC-BY-4.0, редакция `70bb2e84b976b7e960aa89f1c648e09c59f894dd`.
Авторство записей и текстов остаётся у исходного набора; преобразовано только
представление аудио из float WAV в PCM16.

Из официального val выбирается фиксированная небольшая выборка: записи
сортируются по имени файла, для каждого sentence ID берётся первая запись,
затем применяется seed-выборка по отсортированным ID. Список, seed, длительность,
исходные SHA и SHA PCM находятся в `cases.json`. Разные sentence ID не доказывают
разных дикторов: личности из имён файлов не выводятся. Train и test не используются.

`RecordedRussianAsrTest` принимает эту выборку только в изолированном пакете
`.verification`, проверяет SHA и передаёт PCM в Vosk блоками по 250 мс. Каждая
запись проходит два режима: `VoiceCommands.mainGrammar(emptyList())` и свободную
диктовку. Применяется `VoiceHypotheses.decode(..., "main")`; сохраняются исходный
JSON Vosk, текст, уверенность слов, агрегированная уверенность и распознанная
команда. Команды не исполняются. Результаты сегментов объединяются в текст записи.

WER считается по словам после одинаковой нормализации эталона и результата:
Unicode-буквы/цифры, нижний регистр, `ё→е`, удаление пунктуации. Числительные не
преобразуются. Сохраняются замены, удаления, вставки и число эталонных слов;
корпусный WER — сумма ошибок, делённая на сумму эталонных слов, отдельно для
каждого режима. `[unk]` учитывается как слово `unk`. Количество распознанных команд
является наблюдением: у FLEURS нет эталонных команд AgroVoice, поэтому command
accuracy и частота ложных действий здесь не вычисляются.

Это записанная читаемая речь из общей тематики. Проверка не измеряет живую речь,
микрофон, шум поля, гарнитуру, таймауты контроллера, доступность и полный цикл
приложения. Небольшая выборка не оценивает весь FLEURS. V-05/V-08 остаются открытыми.

Подготовка и оценка:

```powershell
.\ml-pipeline\venv\Scripts\python.exe -X utf8 ml-pipeline/assistant/recorded_asr_check.py prepare --dataset ml-pipeline/dataset_asr_ru_fleurs_v1 --out artifacts/verification/fleurs_validation_v1
# Скопировать каталог в external files/fleurs_validation_v1 изолированного APK.
# Установка: adb install -r; запуск: adb shell am instrument с -e class com.agronomy.phytomonitor.RecordedRussianAsrTest.
# После завершения извлечь recognition_results.json из того же каталога.
.\ml-pipeline\venv\Scripts\python.exe -X utf8 ml-pipeline/assistant/recorded_asr_check.py score --cases artifacts/verification/fleurs_validation_v1/cases.json --recognition artifacts/verification/fleurs_validation_v1/recognition_results.json --out docs/android/recorded_asr_2026-10-20/report.json
```

Аудио остаётся в игнорируемом `artifacts/verification`; в репозиторий попадают
только небольшой отчёт, происхождение, расшифровки и методика.
