# AgroVoice AI: APK для проверки фотографий

Версия 0.2-field-demo. Это автономный прототип для ручной проверки модели на реальных листьях. Голос, справочник рекомендаций и сервер будут подключаться отдельно.

Скачать готовый APK (`AgroVoice-field-demo-0.2.apk`; [расположение архива](../ARCHIVE.md)): 90 173 739 байт (86,0 MiB). SHA-256: `9600d3e8cc8b98476bb792ca5260b73894089ab20b43e43d4a46e8e75615c8c0`. Это debug-сборка для личных испытаний, без публикации в магазинах.

## Как пользоваться

1. Открыть AgroVoice AI на Redmi Note 7. APK уже установлен; данные прежнего приложения сохранялись при обновлении.
2. Нажать «Сделать фото» и подтвердить снимок в штатной камере либо «Из галереи» и выбрать одну фотографию.
3. Дождаться рамок и подписей. Обработка происходит на телефоне; модель и изображения на сервер не отправляются.
4. Переключить YOLO11n / YOLO26n для проверки той же фотографии. Кнопки блокируются во время обработки.
5. При необходимости выбрать культуру. Это фильтр результатов: он убирает другие классы, но не превращает ошибочное распознавание в правильное.
6. Порог по умолчанию 0,25. Повышение скрывает слабые предположения, понижение добавляет их вместе с возможными ложными рамками. Уверенность не равна вероятности болезни или доле повреждения.

Фото для проб находятся в общей галерее, каталог `Pictures/AgroVoice_Field_Test`. В системном выборе нажать вкладку «Фотографии»: эта прошивка не показывает отдельный альбом для каждой папки. Список авторов и лицензий — `ATTRIBUTION.txt` рядом с ними.

Модель размечает целые листья. Класс без указанной болезни не гарантирует здоровье растения. Огурец пока имеет один класс «лист, состояние неизвестно»; мучнистую росу, пероноспороз и другие огуречные болезни приложение не диагностирует. Squash из PlantDoc — другой класс, он не заменяет диагноз огурца.

## Какие веса установлены

Обе модели взяты из завершённой пары `study10_v2_*_seed20261003`: одинаковый seed, clean v2, 60 эпох, 30 одинаковых классов. Полная серия из десяти обучений каждой архитектуры завершилась 4 октября в 02:32 Minsk; её средние метрики не относятся к одному выбранному APK. В APK 0.2 сохранена проверенная пара seed 20261003. Итоговая выбранная YOLO26n seed 20261012 доступна отдельным пакетом; [итог и ограничения](../experiments/study10_v2/FINAL_REPORT_2026-10-04.md).

| Модель | Экспорт | Размер ONNX, байты |
|---|---|---:|
| YOLO11n | FP32, обычная Detect-голова + NMS, 416×416 | 10 530 938 |
| YOLO26n | FP32, обычная Detect-голова + NMS, 416×416 | 9 719 842 |

Порядок классов, отпечаток данных, исходные пути и SHA-256: [manifest моделей](field_demo_models_2026-10-03.json). YOLO26n выбрана по умолчанию; пользователь может сравнить обе версии. Выбор по умолчанию не доказывает превосходство на всех культурах.

## Реализация и хранение

Kotlin 2.2.10, Jetpack Compose / Material 3, ONNX Runtime Android 1.30.0, AndroidX ExifInterface 1.4.2, Photo Picker и TakePicture / FileProvider. minSdk 26; arm64-v8a и armeabi-v7a. Проверяемое устройство — Note 7 с Android 13. A56 и Redmi 9T пока не испытаны.

В APK встроены оба графа. Загружена только одна модель; при переключении предыдущая сессия закрывается. Вычисления на CPU: 4 потока внутри графа, один фоновый исполнитель приложения. Фото сначала декодируется с ограничением стороны до 2048 и применением EXIF-поворота/зеркального отражения, затем масштабируется с полями до 416×416, RGB / 255. NMS по классам: IoU 0,7, максимум 300 рамок. Рамки возвращаются в координаты декодированного фото; отображение учитывает поля на экране.

Приложению не предоставлены INTERNET, ACCESS_NETWORK_STATE, микрофон или общий доступ к галерее. Сетевые разрешения и автоматический TelemetryInitializer, добавляемые зависимостью ONNX Runtime, удалены из итогового manifest. Съёмка выполняется приложением камеры, которому FileProvider выдаёт временный доступ к конкретному файлу.

Каждая успешная проверка создаёт JSON с SHA-256 фотографии и модели, культурой, порогом, рамками, confidence и временем обработки. Это технические результаты прототипа; прежняя демонстрационная SQLite-запись не становится настоящим журналом осмотров. Импортированные фото и результаты лежат в личной папке приложения:

```text
/sdcard/Android/data/com.agronomy.phytomonitor/files/photos/
/sdcard/Android/data/com.agronomy.phytomonitor/files/results/
```

Удаление приложения удалит его личные фото и JSON. Примеры в общей галерее останутся. На современных Android извлекать личные результаты удобно через подключённый ADB; обычный файловый менеджер может ограничивать эту папку.

## Проверки

- Сборка и установка через `adb install -r` выполнены без очистки данных.
- Камера открывается, отмена корректно возвращает пользователя в приложение. Физический снимок листа через объектив ещё должен проверить Борис.
- Фото выбрано через настоящий системный Photo Picker, скопировано в личную папку, обработано и сохранено в JSON. Переключение версий и фильтр культуры работают; при отсутствии рамок показано понятное сообщение.
- Обе модели выполнили обработку трёх реальных фото: картофель, томат, огурец. [Результаты на телефоне](phone_validation/summary.json).
- Точный входной тензор телефона проверен через CPU ONNX Runtime на компьютере; все выходы совпали в пределах rtol 1e-4 / atol 0,002. Рамки после NMS совпали с Ultralytics. [Сверка](phone_validation/desktop_parity.json). Это проверка переноса вычислений, не оценка точности по одному снимку.
- Три автоматических теста прошли на Note 7: все восемь EXIF-ориентаций, большое фото с нечётной шириной и повреждённый JPEG. Отдельно проверяется поворот интерфейса между портретной и альбомной ориентацией; итог в [протоколе устройства](phone_validation/verification.json).
- Поворот экрана 0 → 1 → 0 проверен: фото и выбранная модель сохранились, исходные настройки ориентации восстановлены. Lint итоговой сборки: 0 ошибок, 33 предупреждения; A56 и Redmi 9T пока не проверены.
- Числа задержки на отдельных фото в интерфейсе служат обратной связью. Их нельзя выдавать за повторённый сравнительный бенчмарк. Отдельное прежнее исследование по десять серий относилось к clean v1.

При ручной пробе обе версии определили фитофтороз на первом картофельном фото. На томатном фото, которое автор подписал как септориоз, появились другие состояния листьев; на огурце YOLO26n добавила малину и виноград. Эти примеры показывают необходимость расширения полевых данных, а не готовность модели к окончательной диагностике.

## Источники фото и воспроизводимость

Скачаны 10 оригинальных авторских фотографий Wikimedia Commons: 2 картофельных, 6 томатных, 2 огуречных, суммарно 47 274 571 байт. Для каждого сохранены автор, дата, исходная карточка, лицензия, опубликованный SHA-1 и локальный SHA-256. Исходные байты не изменялись. [Manifest фотографий](../../artifacts/field_photos/manifest.json), [атрибуция](../../artifacts/field_photos/ATTRIBUTION.txt).

Один томатный снимок `04_tomato_late_blight.jpg` имеет вероятную похожую копию в train clean v2 (`pd_103327a5b54fcbf318f7.jpg`). Это отмечено в manifest. Остальные не совпали при проверке декодированного хеша и ограниченного pHash/dHash, но такая проверка не доказывает полной независимости. Набор используется для ручной демонстрации, по нему не вычисляется точность и он не добавлен в обучение. У `07_tomato_leaf_mold.jpg` низкое исходное разрешение; это также реальный, но менее полезный для диагностики пример.

Дополнительный одиннадцатый снимок не скачан: сервер запросил паузу 600 секунд после HTTP 429. Загрузки остановлены, сохранённых десяти достаточно для первой проверки; ограничение сервера не обходилось.
