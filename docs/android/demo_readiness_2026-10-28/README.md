# Проверка перед показом — Redmi, 28.10.2026

**Установленная field-версия ошибочно распознаёт выбранную комнатную монстеру
как перец. Требование «вид не поддерживается» не выполнено.** На выбранном
снимке стола детектор не выдал рамок. Это два конкретных примера, а не оценка
надёжности отказа на всех предметах и неизвестных видах.

Числа и фактические тексты: [report.json](report.json), весь прогон —
[device_report.json](device_report.json). Ошибочный снимок не заменялся более
удобным, модель и порог после просмотра ответов не менялись.

## Проверка и воспроизведение

В PowerShell с доступным JDK из каталога `android-app`:

```powershell
.\gradlew.bat assembleFieldDebugAndroidTest
```

Затем установить **только тестовый APK** поверх существующего тестового пакета
через `adb install -r`. Перед инструментированием основного приложения нужна
проверенная копия данных. Поместить требуемые JPG в
`Android/data/com.agronomy.phytomonitor/files/demo-readiness-20261028/` и запустить:

```powershell
adb shell am instrument -w -r -e class com.agronomy.phytomonitor.DemoReadinessDeviceTest -e allowMainDiagnostic true -e images 01_table_no_leaves.jpg,02_houseplant_monstera.jpg com.agronomy.phytomonitor.test/androidx.test.runner.AndroidJUnitRunner
```

В этом прогоне параметр images включал также все 26 изображений нового альбома.
Результат — `installed-detector-report.json` в указанном каталоге приложения.
Без явного параметра allowMainDiagnostic тест пропускается; это не тест для
автоматического изменения или очистки рабочего журнала. `connectedDebugAndroidTest`
не использовался.

Сборка тестового APK успешна, инструментальный прогон — `OK (1 test)`.
Это подтверждает исполнение диагностического кода, **не** успешное выполнение
требований отказа: для монстеры критерий провален. После проверки таблицы
журнала, фото, отчёты, настройки и существовавший черновик совпали с копией до
теста. SQLite integrity_check и foreign_key_check успешны, приложение запущено.
Локальные первичные логи/копии: `artifacts/verification/demo_20261028/ood_check/`.

## Границы и следующий шаг

Экран приложения, кнопочный сценарий, камера и живая речь этим прогоном не
проверены: интерактивные инструменты недоступны. Строка spoken_analysis получена
из функции приложения; фактическое воспроизведение TTS не оценивалось.

В field нет отдельного распознавания неизвестного вида. Экспериментальный
S+DINO доступен в lab, но его отказ также не устанавливает причину
«нет листьев» / «неизвестный вид» / «непригодный кадр». Нельзя подменять эти
разные состояния фиксированной надписью или настройкой под два снимка.
Для следующей работы нужны проверка полной lab-цепочки на Redmi и независимые
примеры разных неизвестных видов/предметов; при выпуске следует сохранять
честный неопределённый отказ, пока различение причин не проверено.
