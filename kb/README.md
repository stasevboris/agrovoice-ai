# Справочник AgroVoice (K-01)

Формат базы знаний о состояниях из `ml-pipeline/allcrops/taxonomy_v1.json`. Сейчас это **каркас**: 49 карточек `draft` без текстов и препаратов. Наполнение — K-02, экран и голос — K-03.

| Файл | Что это |
|---|---|
| `kb_v1.json` | Сама база: список источников и по карточке на каждый класс taxonomy |
| `kb_v1.schema.json` | JSON Schema (draft 2020-12): поля и типы |
| `validate_kb.py` | Схема + смысловые правила; тест — `ml-pipeline/tests/test_kb.py` |

```powershell
.\ml-pipeline\venv\Scripts\python.exe -X utf8 kb\validate_kb.py
```
Нужен пакет `jsonschema` (есть в `ml-pipeline/requirements-accuracy-extra.txt`).

## Карточка

`code`, `crop`, `kind` совпадают с taxonomy. Разделы: `symptoms`, `conditions`, `prevention`, `agrotech` — утверждения `{text, source, locator}`; `treatments` — записи Госреестра РБ; для `nutrition` вместо препаратов `fertilization`. Статус `draft` или `verified` (`verified_by`, `verified_at`, `review_due`).

## Правила валидатора

- Каждый применимый раздел либо заполнен, либо явно отмечен: `missing` — ещё не извлечено, `none_found` — проверено по источникам, данных нет. Пустой раздел без отметки — ошибка: отсутствие информации не оставляется на догадку.
- Каждое утверждение ссылается на источник из `sources` с местом (`locator`); источник указан и в `sources` карточки. `candidate_sources` — очередь работы, а не доказательство.
- Препарат и удобрение — только из источника `by_register` (Госреестр РБ), `registered_in: BY`, с годом и записью реестра. Норма в свободном тексте раздела запрещена.
- Для листа без симптомов препараты не применимы; апельсин — только описание (не выращивается в РБ).
- `verified` требует имени специалиста, дат проверки и пересмотра, источников и отсутствия разделов `missing`.

Нормы и сроки не пишутся из памяти модели или агента. До проверки специалистом карточка остаётся `draft` и не озвучивается как рекомендация.
