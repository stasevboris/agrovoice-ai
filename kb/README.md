# Справочник AgroVoice (K-01)

Формат базы знаний о состояниях из `ml-pipeline/allcrops/taxonomy_v1.json`. Все карточки остаются `draft`: для альтернариоза и фитофтороза картофеля добавлены краткие признаки и условия по B03 с указанием страниц. В 25 карточек перенесены строки Госреестра РБ (320 записей): препарат, норма, кратность и срок ожидания дословно из таблиц с номером страницы. Из Агроэкологического атласа (B21) добавлены признаки, условия развития и профилактика для 13 болезней: яблоня, кукуруза, огурец, тыква, картофель, томат. Специалист их не проверял, поэтому это не рекомендация: приложение показывает их как черновик и не озвучивает. Полнота и проверка источников — [отчёт](../docs/data/KB_PREPARATION_REPORT.json).

В Android доступен офлайн-поиск, фильтр культуры и голосовой выбор карточки. Непроверенные карточки показываются текстом; вместо рекомендации голос сообщает об отсутствии проверки специалистом. Наполнение и экспертная проверка K-02 продолжаются.

| Файл | Что это |
|---|---|
| `kb_v1.json` | Сама база: список источников и по карточке на каждый класс taxonomy |
| `kb_v1.schema.json` | JSON Schema (draft 2020-12): поля и типы |
| `validate_kb.py` | Схема + смысловые правила; тест — `ml-pipeline/tests/test_kb.py` |
| `extract_register_by.py` | Строки таблиц PDF Госреестра РБ для 15 культур → `register_by_rows.json`; PDF не хранятся в git |
| `fill_register_treatments.py` | Переносит подходящие строки реестра в `treatments` карточек (только источник B01) |
| `extract_agroatlas.py` | Признаки, условия и профилактика из Агроэкологического атласа (B21) для проверенного списка страниц |
| `agroatlas_map_v1.json` | Соответствие «класс taxonomy → страница атласа»; составлено вручную, проверяется тестом |

```powershell
.\ml-pipeline\venv\Scripts\python.exe -X utf8 kb\validate_kb.py
.\ml-pipeline\venv\Scripts\python.exe -X utf8 kb\extract_agroatlas.py --dry-run
```
Обновление препаратов: скачать PDF разделов 6.1, 6.3, 6.7, 7.2 со страницы реестра в `artifacts/kb_sources/reestr_by/`, затем
`python -X utf8 kb\extract_register_by.py artifacts\kb_sources\reestr_by --out kb\register_by_rows.json` и
`python -X utf8 kb\fill_register_treatments.py kb\register_by_rows.json` (нужен `pdfplumber`).
Страницы атласа кэшируются в `artifacts/kb_sources/agroatlas/` (в git не идут). Текст цитируется с указанием раздела; нормы препаратов в `symptoms` и `prevention` не переносятся.
Сопоставление «вредный объект → класс» — список слов в `fill_register_treatments.py`; спорные случаи отмечены в примечании записи.
Дополнения реестра 2025–2026 не разбирались: разделы с колонтитулом 16.10.2026 считаются сводной редакцией.

Нужен пакет `jsonschema` (есть в `ml-pipeline/requirements-accuracy-extra.txt`).

## Карточка

`code`, `crop`, `kind` совпадают с taxonomy. Разделы: `symptoms`, `conditions`, `prevention`, `agrotech` — утверждения `{text, source, locator}`; `treatments` — записи Госреестра РБ; для `nutrition` вместо препаратов `fertilization`. Статус `draft` или `verified` (`verified_by`, `verified_at`, `review_due`).

## Правила валидатора

- Каждый применимый раздел либо заполнен, либо явно отмечен: `missing` — ещё не извлечено, `none_found` — проверено по источникам, данных нет. Пустой раздел без отметки — ошибка: отсутствие информации не оставляется на догадку.
- Каждое утверждение ссылается на источник из `sources` с местом (`locator`); источник указан и в `sources` карточки. `candidate_sources` — очередь работы, а не доказательство.
- Препарат и удобрение — только из источника `by_register` (Госреестр РБ), `registered_in: BY`, с годом и записью реестра. Норма в свободном тексте раздела запрещена.
- Для листа без симптомов препараты не применимы; апельсин — только описание (не выращивается в РБ).
- `verified` требует имени специалиста, дат проверки и пересмотра, источников и отсутствия разделов `missing`.

Нормы и сроки не пишутся из памяти модели или агента. До проверки специалистом карточка остаётся `draft` и не озвучивается как рекомендация.
