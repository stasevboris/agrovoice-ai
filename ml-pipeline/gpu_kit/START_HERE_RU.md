# Запуск обучения AgroVoice на RTX 5090

Это готовый маршрут для кафедры: `allcrops_web_v1`, YOLO26 S/N/M и второй seed S.
Интернет нужен для установки Python-пакетов. Данные, начальные веса и шрифт уже внутри.
Нужны установленный Python 3.10–3.13, рабочий драйвер NVIDIA и свободное место
для распаковки, окружения и результатов. Драйверы установщики не меняют.
Скопируйте комплект с внешнего SSD на внутренний SSD машины и распакуйте там.

## 1. Windows — PowerShell

Откройте PowerShell в папке, где лежит перенесённый архив. Для имени комплекта
от 23.10.2026 команды такие; диск и рабочую папку можно выбрать другие.

```powershell
Expand-Archive -LiteralPath .\agrovoice_gpu_kit_20261023.zip -DestinationPath .\training
Set-Location .\training\agrovoice_gpu_kit_20261023
nvidia-smi
powershell -ExecutionPolicy Bypass -File .\setup_windows.ps1
```

После установки отдельно проверьте окружение. Если код выхода не ноль,
устраните напечатанную ошибку, обучение не запускайте.

```powershell
.\.venv\Scripts\python.exe check_env.py
if ($LASTEXITCODE -ne 0) { throw 'Окружение не готово' }
.\.venv\Scripts\python.exe train_queue.py --smoke
if ($LASTEXITCODE -ne 0) { throw 'Пробный прогон не прошёл' }
```

Должны появиться `runs/smoke_yolo26n/run_summary.json` со статусом `done` и
`runs/smoke_yolo26n/weights/best.onnx`. Числа smoke не оценивают качество модели.

Запуск всей очереди с общим бюджетом 6 часов:

```powershell
.\.venv\Scripts\python.exe -u train_queue.py --budget-hours 6 2>&1 | Tee-Object -FilePath .\logs\queue.log -Append
```

`6` замените на реально выделенное время для обучения и оценки, оставив
отдельный запас перед уходом на упаковку и копирование результатов.
Окно PowerShell держите открытым. Проверьте настройки сна компьютера.

## 2. Linux — терминал

```bash
unzip agrovoice_gpu_kit_20261023.zip -d training
cd training/agrovoice_gpu_kit_20261023
nvidia-smi
bash setup_linux.sh
source .venv/bin/activate
python check_env.py
```

При `READY` и коде выхода 0:

```bash
python train_queue.py --smoke
```

Проверьте статус `done` в `runs/smoke_yolo26n/run_summary.json`. Затем:

```bash
set -o pipefail
python -u train_queue.py --budget-hours 6 2>&1 | tee -a logs/queue.log
```

Терминал оставьте открытым. Если используется SSH, можно использовать уже
установленный `tmux`; установка системного ПО не нужна для самого комплекта.

## 3. Какую модель запускать

По умолчанию `queue.json` задаёт S → N → M → S с другим seed. S — основной
мобильный кандидат, N — компактный, M — более тяжёлый контроль.
Если хочется идти от лёгкого к тяжёлому, запускайте по одной: N, затем S, затем M.
Для Windows в командах ниже замените `python` на `.\.venv\Scripts\python.exe`.

```bash
python -u train_queue.py --budget-hours 2 --only allcrops_web_v1_yolo26n_416_s20261003
python -u train_queue.py --budget-hours 2 --only allcrops_web_v1_yolo26s_416_s20261003
python -u train_queue.py --budget-hours 2 --only allcrops_web_v1_yolo26m_416_s20261003
```

Это три отдельных запуска, не выполнять их параллельно. Числа `2` — примеры
выделенного бюджета, не прогноз длительности. В очереди также заданы пределы
на одну модель: N — 0,8 ч, S — 1,4 ч, M — 1,6 ч. Увеличение общего бюджета
само по себе не отменяет эти пределы: при необходимости измените `hours` у
нужной строки `queue.json` до начала опыта и сохраните этот файл с результатами.

План — до 60 эпох, ранняя остановка после 15 эпох без улучшения. Если эпохи не
помещаются в выделенный лимит, скрипт сокращает фактический бюджет обучения.
Скорость и завершение всех 60 эпох на 5090 заранее не гарантируются.
`--budget-hours` не является внешним жёстким выключателем процесса:
завершающая оценка/экспорт может занять дополнительное время. Если у кафедры
есть точное время освобождения машины, остановите очередь заранее через `STOP`
и оставьте время на проверку и копирование результатов.

`check_env.py` пишет настройки загрузки данных и batch в `env.json`. На NVIDIA
сначала используйте их. Если не хватает видеопамяти, уменьшите `batch` у нужной
модели в `queue.json`; изменение параметров обязательно учитывать в сравнении.

## 4. Наблюдение и остановка

В другом окне Windows:

```powershell
Get-Content .\logs\queue.log -Tail 20 -Wait
```

Linux:

```bash
tail -f logs/queue.log
```

Метрики по эпохам — `runs/<имя>/results.csv`. Статус модели —
`runs/<имя>/run_summary.json`. Итог `done` означает, что завершены обучение,
оценка и экспорт. Одна строка `Queue finished` не доказывает успех всех моделей:
очередь может продолжить работу после ошибки отдельной модели.

Мягкая остановка: в корне распакованного комплекта создать пустой файл `STOP`.

```powershell
New-Item -ItemType File -Path .\STOP
```

```bash
touch STOP
```

Дождитесь завершения текущей эпохи и выхода процесса. При такой остановке
оценка/экспорт ещё могут отсутствовать — это штатно. Для продолжения на той же
машине переименуйте только управляющий файл, сохранив данные и checkpoints:

```powershell
Rename-Item -LiteralPath .\STOP -NewName ('STOP.saved.' + (Get-Date -Format yyyyMMdd_HHmmss))
```

```bash
mv STOP "STOP.saved.$(date +%Y%m%d_%H%M%S)"
```

Повторите прежнюю команду очереди. Готовые `done` пропускаются; прерванные
возобновляются по `weights/last_resumable.pt`. После переноса на другую машину
пути в checkpoint могут не совпасть; автоматическое продолжение между разными
ОС не проверено. Простой повтор готовой очереди не запускает новый опыт.

## 5. Забрать результаты

После выхода процесса обучения:

```powershell
.\.venv\Scripts\python.exe package_results.py
```

или Linux:

```bash
python package_results.py
```

Получится `results_<компьютер>_<дата>.zip`. Скопируйте его на внешний SSD.
Проверьте архив командой (подставьте его точное имя):

```bash
python -m zipfile -t results_COMPUTER_YYYYMMDD_HHMM.zip
```

Главное содержимое: `best.pt`, `last.pt`, `last_resumable.pt`, `best.onnx`,
`results.csv`, `args.yaml`, `run_summary.json`, `eval/evaluation.json`,
`android_manifest_entry.json`, `env.json`, `queue.json` и логи.
У прерванного запуска ONNX и итоговой оценки может ещё не быть.
Не удаляйте исходные результаты, пока копия не проверена.

## 6. Что этот комплект не доказывает

В наборе представлены 49 классов / 15 культур, но веб-метки слабые, некоторые
рамки требуют просмотра, а полевая оценка не покрывает все классы. Отдельного
обучения отказу на предметах в этой очереди нет. Полный список ограничений —
в документации проекта и `README.md`. Метрики обучения не означают подтверждённую
работу в поле. Test здесь исторический и вычисляется после каждой модели;
не использовать его для подбора порогов или архитектуры.

После возвращения: сравнение обычной ONNX-головы с моделью APK на одинаковых
кадрах, проверка на телефоне и только затем решение о замене модели.
Никакой автоматической публикации в этом комплекте нет.
